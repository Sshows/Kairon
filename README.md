# Kairon

Сайт: [kairon-phi.vercel.app](https://kairon-phi.vercel.app). Данные первого администратора сохранены отдельным локальным файлом и не включены в репозиторий.

Образовательная платформа по кибербезопасности для начинающих. Сайт объясняет на простом русском языке, ученик выполняет практику в собственной Kali Linux. Оболочка переключается на английский; текущие уроки написаны на русском.

**Рабочий курс:** [Kali Linux с нуля](https://kairon-phi.vercel.app/paths/from-zero) — 20 уроков в четырёх уровнях. [Начать с готовой машины](https://kairon-phi.vercel.app/learn/kali-install), [книги и проекты](https://kairon-phi.vercel.app/resources).

**Новый путь:** [Безопасность в компании](https://kairon-phi.vercel.app/paths/blue-team) — 12 практических дел, 1360 XP и отдельный набор вымышленных событий. [Первая смена](https://kairon-phi.vercel.app/learn/soc-first-shift). Оба пути можно начинать независимо; у каждого собственные порядок уроков, прогресс и файлы.

**Свои программы с нуля:** [Свои первые инструменты](https://kairon-phi.vercel.app/paths/kali-tools) — 8 уроков, 900 XP: первая строка Python, хеши, Base64, учебный шифр, заголовки ответа, подсчёт входов, проверка копий и отчёт. [Начать](https://kairon-phi.vercel.app/learn/project-start). Отдельный набор — 15 файлов, семь собственных небольших программ без сетевых запросов и внешних зависимостей.

**Все темы Cybersecurity-Projects:** [69 карточек проектов](https://kairon-phi.vercel.app/projects) с объяснением, пользой, необходимыми понятиями, планом и ссылками на точную версию автора. У 43 есть исходники, у 26 — только описание идеи; это не 69 приложений, развёрнутых на Kairon. Дополнительно — десять карьерных направлений и пять групп ресурсов. [Аудит и лицензия AGPL-3.0](docs/source-audits/carter-projects.md).

В версии 0.5 все 32 прежних урока переписаны понятнее: новые слова, команды и поля таблиц объясняются на месте, шаги сопровождаются ожидаемым результатом. IDs, правильные ответы и заработанные XP сохранены. Теперь три независимых пути, 40 уроков и максимум 4390 XP.

**Источник новых тем:** [разбор «Карманного хакера»](https://kairon-phi.vercel.app/sources/pocket-hacker) — 258 доступных публичных записей, 254 с текстом, на 13 страницах. Просмотрены тексты и подписи, без содержимого PDF/видео/изображений, комментариев и закрытого платного архива. Новые тексты и упражнения написаны для Kairon; указаны посты и первичная документация. [Аудит](docs/source-audits/pocket-hacker.md).

## Что доступно

- Запуск готового образа VirtualBox: официальные загрузки, распаковка, выбор .vbox, первый вход kali/kali, замена пароля и снимок.
- Firefox/Chromium и Tor Browser с объяснением установки и границ приватности.
- Учебные расследования: подозрительный файл, подмена документа, письмо, журнал входа и права файлов.
- Свой локальный HTTP-сайт, один порт Nmap, ответы 200/404, искусственный PCAP для Wireshark.
- Собственный безвредный процесс, тест антивируса EICAR из официального источника, восстановление из копии, отчёт и финальное дело.
- Скачиваемый ZIP с авторскими вымышленными данными, исходниками, SHA256 и проверками. В архиве нет вредоносного кода и EICAR.
- Самопроверка ответа без регистрации. Гостевой результат не сохраняется после обновления страницы.
- Для аккаунтов: FORCE RLS, прогресс, максимум 2130 XP в Kali и 1360 XP в пути компании, до трёх подсказок по −10 XP, атомарный зачёт без повторного начисления, лимит 20 ответов за минуту на урок.

## Как учиться

Читай любой гайд, открывай официальные ссылки рядом, выполняй шаги в своей Kali. Отмечай проверенный результат и отвечай на вопрос. Сайт проверяет ответ на вопрос: он не видит и не аттестует состояние компьютера ученика. Чек-лист помогает самому ученику, его галочки не отправляются.

Аккаунт по приглашению нужен только для долговременного прогресса и XP. Для зачёта в аккаунте принимаются правила и соблюдается порядок уроков. Старые результаты сохранены в общем XP, но не увеличивают счётчик нового курса.

Браузерный терминал, его интерпретатор, CSS и прежний setup-скрипт удалены. Старый /terminal перенаправляет к установке Kali; старые ссылки уроков — к соответствующим новым гайдам. Новая инфраструктура Kali/VPS/Render не требуется: программы выполняются у ученика.

## Техническое состояние

Next.js 16.4.3 App Router, TypeScript, React, Tailwind 4, Auth.js Credentials и Prisma 7.10.1/PostgreSQL. Существующие User, AuditLog, LoginAttempt и LessonProgress с FORCE RLS и ограниченной runtime-ролью. Учебные тексты в content/lessons/kali.json и content/lessons/company.json. Правильные ответы, подсказки и разбор не входят в публичные props.

Полного редактора контента, AI-наставника, сертификатов и двух остальных направлений пока нет. Подтверждённые проверки — в [статусе](docs/verification.md), устройство курса — в [описании релиза](docs/learning-release.md).

## Быстрый запуск интерфейса

Нужен Node.js 22.12+ или 24 LTS и npm. Проверенная линия Prisma — 7.10.1; prerelease Prisma 8 не используется.

```bash
npm ci
npm run db:generate
npm run build
npm run start
```

Открой `http://localhost:3000`. Без настроенной БД можно читать уроки, скачивать набор, проверять учебный ответ, искать темы и пользоваться словарём. Войти или получить учебный прогресс в таком режиме нельзя.

Для разработки: `npm run dev`. Для проверки: `npm run lint`, `npm run typecheck`, `npm test`. Внешние шрифты при сборке не загружаются.

## Настройка существующего Neon

Используется отдельная база Kairon. Не направляй миграции в чужую заполненную базу: миграция создаёт таблицы, роли, функции и политики в public. Перед первым применением проверь целевой проект/ветку/базу. Development/Preview должны использовать отдельную ветку или базу от Production.

1. `npm run env:init` создаст игнорируемый `.env.local` с новым AUTH_SECRET. Существующий файл не перезаписывается.
2. В локальном редакторе укажи `DIRECT_URL` владельца выделенной базы Neon. Пароли и DSN не публикуются и не передаются в чат.
3. `npm run db:migrate` применит SQL. Роль миграций должна иметь право создавать роли; на Neon это нужно проверить для выбранного аккаунта. Миграция запрещает runtime с повышенными привилегиями/членством в других ролях.
4. `npm run db:provision` задаст случайный пароль `kairon_runtime` и допишет DATABASE_URL в `.env.local`, не печатая значение. Скрипт не ротирует уже настроенную роль. Для production используй pooled endpoint Neon в DATABASE_URL; DIRECT_URL оставь прямым только для CLI.
5. `npm run db:check` проверит реальную PostgreSQL: FORCE RLS, чужие строки/записи, очистку контекста, запрет повышения роли и лимит входа. Пропущенных тестов нет: без DSN команда завершается ошибкой.
6. Создай аккаунт через CLI ниже, затем запусти приложение и войди. На первой практике пользователь должен принять правила; Этап 0 сохраняет согласие и разрешает зачёт курса.

**DIRECT_URL не добавляется в runtime Vercel.** Веб-приложение должно работать только как `kairon_runtime`. При первом доступе оно проверяет, что роль не владелец таблиц, не superuser/BYPASSRLS и не член других ролей; неправильная конфигурация закрывает доступ. Не выдавай пользователям прямое подключение к этой БД: контекст RLS задаёт доверенный сервер, а не браузер.

## Выдача и блокировка аккаунтов

Администратор локально добавляет в `.env.local` временные переменные:

```dotenv
KAIRON_ACCOUNT_EMAIL=
KAIRON_ACCOUNT_NAME=
KAIRON_ACCOUNT_PASSWORD=
KAIRON_ACCOUNT_ROLE=ADMIN
```

Пароль: минимум 12 символов, максимум 72 байта UTF-8. Для обычного аккаунта роль USER. Выполни:

```bash
npm run account -- create
npm run account -- block
npm run account -- unblock
```

Для block/unblock достаточно KAIRON_ACCOUNT_EMAIL и DIRECT_URL. После создания убери временный пароль из файла и передай пользователю по согласованному безопасному каналу. Команды не печатают пароль. Блокировка увеличивает sessionVersion, старые сессии больше не принимаются. Веб-управление аккаунтами планируется отдельно.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run db:check
python -B tests/kali_kit_test.py -v
python -B tests/company_kit_test.py -v
npm run build
npx playwright install chromium
npm run test:e2e
```

`db:check` и `test:e2e` используют реальную БД и создают временные тестовые аккаунты. Запускай их только на выделенной тестовой базе. Браузерные тесты проверяют открытый гайд и архив, гостевую самопроверку, все 32 ответа в аккаунте и независимые очереди двух курсов, XP/подсказки/историю старого курса, USER/ADMIN и отзыв сессии. CI создаёт отдельную PostgreSQL service database и одноразовый runtime-пароль; секреты Neon и Vercel ему не нужны. Тестовые данные очищаются по своим UUID. Trace отключён. В артефакты загружаются только публичные скриншоты без данных авторизации.

## Vercel

После успешных локальных и CI-проверок импортируй `Sshows/Kairon`, framework Next.js, root — корень репозитория, Node.js 24, build `npm run build`. Сначала можно опубликовать каталог с отключённым входом. Затем добавь DATABASE_URL ограниченной роли и отдельный AUTH_SECRET (32+ случайных символа) для нужного окружения. AUTH_URL — канонический HTTPS-адрес. После изменения переменных нужен новый deployment.

Миграции и первый аккаунт выполняются доверенным CLI отдельно от build/deploy. Vercel отдаёт гайды и API самопроверки; Kali и инструменты запускаются на машине ученика. Отдельный сервер для терминала не используется. Доступ к текущей Vercel-команде и Neon должен быть подтверждён интеграцией; наличие конфигурации в Git не означает успешный деплой.
