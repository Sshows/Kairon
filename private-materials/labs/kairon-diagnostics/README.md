# Kairon: почему учебный портал не открывается

Собственный вымышленный случай DIAG-28. Только тексты и таблицы: ничего устанавливать, запускать на сервере или отправлять в сеть не требуется. Адрес portal.example и диапазон 192.0.2.0/24 используются в документации; работающего портала по этим адресам в наборе нет.

## Как работать

Распакуй набор в домашнюю папку Kali. Ожидаемый путь: ~/kairon-diagnostics. Прочитай READY.txt: в нём DIAG-READY-28. Уроки используют cat и grep для чтения местных файлов. Свой отчёт сохраняй как копию reports/template.md. Для упражнений нужны только обычные права пользователя.

## Файлы

- case-notes.txt: постановка задачи, границы, снимок настроек и действия владельца учебного стенда.
- client-observations.csv: три разных обращения клиентов.
- scope-map.csv: где находится клиент и что для него означает адрес.
- dns-snapshots.txt: сохранённые наблюдения DNS и HTTP.
- tls-observations.csv: сохранённые результаты проверок сертификата OpenSSL, а не сертификаты или программа для запросов.
- access.txt и error.txt: собственный упрощённый формат журналов учебного шлюза, не настоящий вывод nginx. Шлюз по своей учебной политике переводит отказ соединения с приложением в HTTP 503. Это не утверждение о стандартном коде ответа nginx.
- capacity-snapshots.csv: собственная сводка сохранённых наблюдений df по двум разным узлам; байты и inode указаны раздельно.
- disk-usage.csv: сохранённая сводка du; отдельные пути могут входить в родительские каталоги, строки нельзя механически складывать.
- change-options.csv: варианты плана на бумаге, не готовые команды.
- verification.csv: результаты вымышленной проверки после change-b.
- reports/template.md: бланк собственных выводов.

Все времена UTC. Буква Z в конце даты обозначает UTC. В дополнительных карточках TLS намеренно неверные часы клиента; реальное время случая указано отдельно. Узел archive-node — отдельный пример расхода inode: его состояние не доказывает причину ошибки /orders на portal-node.
