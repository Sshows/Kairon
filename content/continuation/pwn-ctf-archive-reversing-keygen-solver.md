## Перед началом: Архив соревнований `pwn.college CTF Archive` (`github.com/pwncollege/ctf-archive`): реверс-инжиниринг и генераторы ключей (`Keygen / Flag Solver`)

На платформе **`pwn.college` (`https://pwn.college/ctf-archive`)** и в открытом репозитории **`github.com/pwncollege/ctf-archive`** собраны сотни реальных задач с крупнейших мировых CTF-турниров (`CSAW CTF`, `UIUCTF`, `BuckeyeCTF`, `åNgstromCTF`, `DiceCTF`, `0CTF`, `DEF CON Quals`), пересобранных так, чтобы каждый студент мог запустить их прямо в браузере или в локальном контейнере.

В категории **`Reverse Engineering (Реверс-инжиниринг)`** большинство задач `CTF Archive` устроены по схеме **обратимого побайтового конвейера (`Invertible Byte Pipeline`)**:
1. Бинарная программа считывает введённую пользователем строку `flag` длины $N$.
2. К каждому байту `b` на позиции `i` последовательно применяются несколько обратимых битовых операций в кольце по модулю 256 ($\pmod{256}$):
   - **Побитовый `XOR` с константой или индексом**: $x_1 = b \oplus (0x5A + i)$. Обратная операция — **тот же самый `XOR`**: $b = x_1 \oplus (0x5A + i)$.
   - **Циклический сдвиг битов влево на $k$ разрядов (`ROL8 — Rotate Left 8-bit`)**:
     $$\text{ROL}_8(x, k) = ((x \ll k) \mid (x \gg (8 - k))) \ \& \ 0xFF$$
     В отличие от обычного сдвига `<<`, при котором вытолкнутые слева старшие биты теряются навсегда, циклический сдвиг `ROL8` переносит их в младшие разряды справа! Поэтому у `ROL8(x, k)` всегда есть точная обратная операция — **циклический сдвиг вправо на $k$ разрядов (`ROR8`)**!
   - **Модульное сложение (`ADD mod 256`)**: $x_3 = (x_2 + C) \bmod 256$. Обратная операция — **модульное вычитание**: $x_2 = (x_3 - C) \bmod 256$.
3. В конце функция `check_flag()` сравнивает полученный массив байтов с зашитым в секции `.rodata` массивом констант `TARGET_BYTES`.

## Почему это работает: Принцип обращения композиции функций $(f \circ g \circ h)^{-1} = h^{-1} \circ g^{-1} \circ f^{-1}$

Представь, что ты сначала надел носки ($h$), потом ботинки ($g$), а сверху завязал шнурки ($f$). Чтобы разуться, нужно выполнять обратные действия **строго в обратном порядке**: сначала развязать шнурки ($f^{-1}$), потом снять ботинки ($g^{-1}$), и только потом снять носки ($h^{-1}$)!
Точно так же в реверс-инжиниринге: если проверка флага делает `XOR -> ROL8 -> ADD`, то твой скрипт-решатель (`Solver`) берёт целевой массив `TARGET_BYTES` из `.rodata` и применяет к нему обратные операции в обратном порядке: **`SUB -> ROR8 -> XOR`**!

## Сделай сейчас: Напиши обратимый CTF-решатель (`SUB -> ROR8 -> XOR`) в `lab.py`

### Шаг 1. Создай файл `lab.py`

Создай скрипт `lab.py`:

```python
def rol8(val, shift):
    shift &= 7
    return ((val << shift) | (val >> (8 - shift))) & 0xFF


def ror8(val, shift):
    shift &= 7
    return ((val >> shift) | (val << (8 - shift))) & 0xFF


def check_flag_forward(candidate_str):
    out = []
    for idx, ch in enumerate(candidate_str.encode("ascii")):
        step1 = ch ^ ((0x33 + idx * 7) & 0xFF)
        step2 = rol8(step1, 3)
        step3 = (step2 + 0x29) & 0xFF
        out.append(step3)
    return out


def solve_flag_inverse(target_array):
    recovered = bytearray()
    for idx, target_byte in enumerate(target_array):
        # Обратный порядок: сначала вычитаем 0x29, затем ROR8 на 3, затем XOR
        inv_step2 = (target_byte - 0x29) & 0xFF
        inv_step1 = ror8(inv_step2, 3)
        orig_byte = inv_step1 ^ ((0x33 + idx * 7) & 0xFF)
        recovered.append(orig_byte)
    return recovered.decode("ascii")


# Массив из секции .rodata бинарника CTF-задачи
RODATA_TARGET = [236, 108, 161, 194, 137, 57, 1, 2, 242, 226, 162, 39, 111, 87, 112]

flag = solve_flag_inverse(RODATA_TARGET)
print("recovered_ctf_flag=", flag)
print("forward_matches_rodata=", check_flag_forward(flag) == RODATA_TARGET)
print("rol_ror_identity=", ror8(rol8(0xAB, 3), 3) == 0xAB)
```

### Шаг 2. Запусти программу и проверь восстановленный флаг CTF

Разберём, как сработал решатель:
- для каждого байта из `RODATA_TARGET` функция `solve_flag_inverse` сначала обратила модульное сложение (`(target_byte - 0x29) & 0xFF`), затем вернула биты на место циклическим сдвигом вправо `ror8(..., 3)`, и в конце сняла маску `XOR` с `(0x33 + idx * 7)`;
- в результате за долю миллисекунды была восстановлена точная строка `KRN{CTF_REV_OK}`, которая при подаче в `check_flag_forward` даёт стопроцентное совпадение с `RODATA_TARGET` (`forward_matches_rodata= True`).


## Почему это работает: Когда работает побайтовый перебор (`256 * N`), а когда нужен `Z3`

Если в функции `check_flag` каждый байт `flag[i]` преобразуется **независимо от соседних байтов**, то вместо перебора $256^{15}$ комбинаций достаточно подобрать по очереди все 256 вариантов для позиции `0`, затем 256 вариантов для позиции `1` и так далее — всего $15 \times 256 = 3840$ микросекундных операций! А если байты перемешаны между собой (например, `flag[i] + flag[i+1] == ...`), на помощь приходит решатель ограничений `Z3`, который мы разбирали в предыдущем модуле.

## Если не получилось: Частые ошибки

- **Забывать маску `& 0xFF` при сдвиге влево в Python**: в языке C тип `uint8_t` сам обрезает число до 8 бит, но в Python целые числа имеют бесконечную разрядность! Без `& 0xFF` выражение `val << 3` сохранит биты старше седьмого и исказит результат `rol8`.
