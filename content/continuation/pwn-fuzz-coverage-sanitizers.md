## Перед началом: Как фаззер сам находит глубокие ошибки в парсерах по обратной связи от веток кода

В практикуме **Fuzz Dojo (`fuzz`)** на платформе `pwn.college` изучают один из самых результативных методов современного поиска уязвимостей (0-day) и тестирования надёжности программ: **мутационный фаззинг с обратной связью по покрытию кода (Coverage-Guided Fuzzing — AFL++, LibFuzzer)** в связке с компиляторными детекторами ошибок памяти **ASan (AddressSanitizer)** и **UBSan (UndefinedBehaviorSanitizer)**.

Представь, что перед тобой сейф с четырьмя кодовыми дисками.
- Если пытаться угадать код методом **«слепого фаззинга» (Black-box / Blind Fuzzing)**, ты просто крутишь все четыре диска наугад: вероятность угадать 4-буквенное слово `"KRN!"` с одной попытки равна $\frac{1}{256^4} = \frac{1}{4\,294\,967\,296}$ (один шанс из четырёх миллиардов!).
- А теперь представь, что к механизму сейфа подключён стетоскоп (**инструментация покрытия кода — Coverage Instrumentation**), который слышит тихий щелчок каждый раз, когда угадана очередная правильная буква и программа зашла в новую, ранее не посещаемую ветку `if`! Как только фаззер случайно поставил на первом диске букву `'K'`, раздался щелчок («открыта новая ветка `edge_1`!»). Фаззер тут же **сохраняет этот удачный вход в свою коллекцию (Corpus)** и начинает слегка менять (мутировать) уже его! В результате на поиск всех четырёх букв уходит не 4 миллиарда попыток, а всего несколько сотен!

## Почему это работает: Инструментация базовых блоков, корпус входов (Corpus) и санитайзеры ASan/UBSan

Разберём три составляющих современного фаззинга (AFL++ / LibFuzzer):

1. **Обратная связь по покрытию рёбер графа (Edge / Branch Coverage)**:
   - при компиляции тестируемой программы с флагом `-fsanitize=fuzzer` (или `afl-clang-fast`) компилятор автоматически вставляет в начало каждого базового блока и каждой ветки `if`/`switch` крошечную метку — счётчик переходов `cov_map[edge_id]++`;
   - после каждого запуска `LLVMFuzzerTestOneInput(data, size)` фаззер проверяет битовую карту `cov_map`: открыл ли этот вход хотя бы одно новое ребро графа, где программа раньше ещё ни разу не бывала?
2. **Эволюция корпуса (Seed Corpus & Mutation)**:
   - если вход не открыл новых веток, он отбрасывается;
   - если же вход открыл новую ветку (например, прошёл проверку первых двух байтов заголовка `magic == "KR"`), фаззер **добавляет его в корпус (`Corpus`)** и применяет к нему быстрые мутации (инверсию отдельных битов, замену байта, вставку граничных чисел `0`, `-1`, `0x7FFFFFFF`, склейку двух входов). Так программа шаг за шагом проникает сквозь самые сложные многоступенчатые проверки!
3. **Зачем фаззеру нужны санитайзеры `ASan` и `UBSan`**:
   - без санитайзера выход за границу буфера на 1 байт или чтение после освобождения (`Use-After-Free`) может не уронить программу сразу, и фаззер просто не заметит ошибку;
   - когда программа собрана с **`-fsanitize=address,undefined` (ASan + UBSan)**, компилятор окружает каждый буфер на стеке и в куче защитными «красными зонами» (**Redzones**) и ведёт теневую карту памяти (**Shadow Memory**). При малейшем чтение или записи даже на 1 байт за границу буфера `ASan` мгновенно останавливает программу и печатает точный отчёт с номером строки!

## Сделай сейчас: Практика: сравни слепой перебор с фаззингом по покрытию веток и детектором `ASan`

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
def parse_packet_with_asan(buf):
    edges = {"entry"}
    if len(buf) < 4:
        return "ok", edges
    if buf[0:1] == b"K":
        edges.add("b0_K")
        if buf[1:2] == b"R":
            edges.add("b1_R")
            if buf[2:3] == b"N":
                edges.add("b2_N")
                if buf[3:4] == b"!":
                    edges.add("b3_bang_bug")
                    return "ASAN_TRAP:heap-buffer-overflow_at_offset_4", edges
    return "ok", edges


def run_coverage_guided_fuzzer(seed=b"AAAA", candidate_bytes=b"XYZKRN!"):
    corpus = [bytearray(seed)]
    seen_edges = {"entry"}
    executions = 0

    for pos in range(4):
        current = bytearray(corpus[-1])
        for ch in candidate_bytes:
            executions += 1
            trial = bytearray(current)
            trial[pos] = ch
            status, edges = parse_packet_with_asan(bytes(trial))
            if edges - seen_edges:
                seen_edges |= edges
                corpus.append(trial)
                if status.startswith("ASAN_TRAP"):
                    return status, bytes(trial), executions, len(corpus)
                break
    return "no_bug_found", bytes(corpus[-1]), executions, len(corpus)


status, crash_input, execs, corpus_size = run_coverage_guided_fuzzer()
print("fuzz_result=", status)
print("crashing_input=", crash_input, "total_execs=", execs, "corpus_saved=", corpus_size)
```

### Шаг 2. Запусти программу и посмотри, за сколько запусков найден баг

В терминале выполни:

```bash
python3 lab.py
```

**Ожидаемый результат на экране:**

```text
fuzz_result= ASAN_TRAP:heap-buffer-overflow_at_offset_4
crashing_input= b'KRN!' total_execs= 22 corpus_saved= 5
```

Посмотри на цифры:
- функция `parse_packet_with_asan` содержит глубокую ошибку, которая срабатывает только тогда, когда все четыре байта заголовка одновременно равны `b"KRN!"`;
- благодаря тому, что после каждой новой открытой ветки (`b0_K`, `b1_R`, `b2_N`, `b3_bang_bug`) условие `if edges - seen_edges:` сохраняло прогресс в коллекцию `corpus`, фаззер нашёл вход `b'KRN!'` и вызвал срабатывание санитайзера `ASAN_TRAP:heap-buffer-overflow_at_offset_4` всего за **22 запуска** (`total_execs= 22`), сохранив в корпусе 5 промежуточных шагов (`corpus_saved= 5`)!

### Шаг 3. Проверь, что происходит, если отключить сохранение корпуса по покрытию

В файле `lab.py` проверь, что случится, если фаззер перестанет брать последний лучший элемент из `corpus[-1]`, а будет каждый раз мутировать исходный `seed`: измени строку `current = bytearray(corpus[-1])` на `current = bytearray(corpus[0])`, сохрани и запусти `python3 lab.py`. Без накопления успешных мутаций в корпусе фаззер застрянет на первой же букве и вернёт `fuzz_result= no_bug_found` (`crashing_input= b'KAAA'`). После проверки верни `current = bytearray(corpus[-1])`.

В терминале Kali ты можешь проверить, как `LibFuzzer` и `AFL++` вычисляют имя файла в корпусе по его `SHA-1` хешу, чтобы не дублировать входы:

```bash
python3 -c 'import hashlib; print("corpus_input_sha1=", hashlib.sha1(b"KRN!").hexdigest()[:12])'
```

## Почему это работает: Как писать собственные обёртки для фаззинга (Fuzz Targets / Harnesses)

В современной разработке безопасного ПО (OSS-Fuzz) для каждой функции разбора сетевых пакетов, изображений, архивов или конфигураций пишут короткую функцию-обёртку (Fuzz Target), которая принимает произвольный массив байтов `(data, size)` и подаёт его в парсер при включённых `ASan` и `UBSan`. В Python для такого же фаззинга с обратной связью по покрытию байткода используется библиотека **Atheris** и фреймворк тестирования свойств **Hypothesis**.

## Если не получилось: Частые ошибки

- **Использование контрольных сумм (`CRC32`) внутри кода во время фаззинга без их стаббирования**: если парсер в самом начале проверяет 32-битную контрольную сумму `CRC32` всего пакета, то любая однобайтовая мутация фаззера будет отбрасываться на проверке `CRC32` до того, как дойдёт до основного кода. Поэтому на время фаззинга проверку `CRC32` либо условно отключают макросом `#ifdef FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`, либо автоматически пересчитывают в самой обёртке фаззера.
