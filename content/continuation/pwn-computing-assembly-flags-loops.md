## Перед началом: Как процессор считает адреса без обращения к памяти и как устроены циклы в ассемблере

В модулях **Assembly Assortment** и **Control Flow** курса **Computing 101** (`pwn.college`) разбирают инструкции, которые встречаются буквально в каждой второй строке дизассемблированного кода `x86-64`: вычисление эффективного адреса **`lea` (Load Effective Address)**, побитовые сдвиги **`shl` / `shr`**, разницу между знаковыми (`jl` / `jg`) и беззнаковыми (`jb` / `ja`) переходами и устройство счётчиков циклов.

Начинающих реверс-инженеров чаще всего ставит в тупик инструкция `lea rax, [rdi + rsi*4 + 16]`. Квадратные скобки `[...]` в ассемблере обычно означают «сходи в оперативную память по этому адресу и прочитай оттуда байты» (как в `mov rax, [rdi]`). Но инструкция **`lea`** — хитрое исключение! Она вообще **не обращается к оперативной памяти**: она просто использует быстрый адресный калькулятор процессора, чтобы за один такт посчитать арифметическое выражение `rdi + rsi*4 + 16` и положить само получившееся число в регистр `rax`! Именно поэтому компиляторы GCC и Clang постоянно используют `lea` для быстрого сложения и умножения на `2, 3, 4, 5, 8, 9`.

## Почему это работает: Инструкция `lea`, сдвиги `shl`/`shr` и флаги знаковых/беззнаковых переходов

Разберём четыре правила чтения ассемблерного кода `x86-64`:

1. **Чем `mov reg, [addr]` отличается от `lea reg, [addr]`**:
   - `mov rax, [rbx + rcx*8]` вычисляет адрес `rbx + rcx*8`, идёт по этому адресу в оперативную память и читает оттуда 8 байт в `rax` (аналог разыменования указателя `*ptr` в C);
   - `lea rax, [rbx + rcx*8]` вычисляет ту же самую формулу `rbx + rcx*8` и записывает **само вычисленное число** в `rax`, даже если этот адрес вообще не существует в памяти (аналог взятия адреса `&arr[i]` или обычной формулы `rbx + rcx * 8`).
2. **Побитовые сдвиги (`shl` и `shr`) как быстрое умножение и деление на степени двойки**:
   - сдвиг влево на $k$ бит (`shl rax, k` или `x << k`) дописывает справа $k$ нулевых битов, что равносильно умножению на $2^k$ (например, `shl rax, 3` умножает на $2^3 = 8$);
   - логический сдвиг вправо (`shr rax, k` или `x >> k`) делит беззнаковое число на $2^k$ нацело, отбрасывая младшие $k$ бит.
3. **Знаковые (`jl`/`jg`) против беззнаковых (`jb`/`ja`) условных переходов после `cmp A, B`**:
   - в `x86-64` одна и та же инструкция `cmp A, B` вычитает `A - B` и выставляет сразу несколько флагов в регистре `RFLAGS`: флаг нуля `ZF` (равенство), флаг переноса `CF` (беззнаковый заём, когда беззнаковое $A < B$), флаг знака `SF` (знак результата) и флаг знакового переполнения `OF`;
   - если числа **беззнаковые** (`size_t`, `uint64_t`), компилятор ставит переходы **`jb` (Jump if Below, `CF == 1`)** и **`ja` (Jump if Above)**;
   - если числа **знаковые** (`int`, `long`), компилятор ставит переходы **`jl` (Jump if Less, `SF != OF`)** и **`jg` (Jump if Greater)**;
   - поэтому в дизассемблере по одному только названию перехода (`jb` или `jl`) ты сразу видишь, какой тип переменной (`unsigned` или `signed`) был в исходном коде!
4. **Как устроен цикл в ассемблере (`loop_header` / `loop_body`)**. Любой цикл `for (int i = 0; i < n; i++)` в машинном коде состоит из инициализации счётчика (`xor ecx, ecx` — быстрый способ обнулить регистр `rcx`), тела цикла, шага инкремента (`add rcx, 1`) и сравнения с границей (`cmp rcx, rdi` → `jb loop_body`).

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
MASK64 = (1 << 64) - 1


def eval_lea(base, index, scale, disp):
    if scale not in (1, 2, 4, 8):
        raise ValueError("Invalid x86-64 scale")
    return (base + index * scale + disp) & MASK64


def compare_jumps_u8(a_byte, b_byte):
    u_a, u_b = a_byte & 0xFF, b_byte & 0xFF
    s_a = u_a - 256 if u_a >= 0x80 else u_a
    s_b = u_b - 256 if u_b >= 0x80 else u_b
    return {
        "je_equal": u_a == u_b,
        "jb_unsigned_below": u_a < u_b,
        "jl_signed_less": s_a < s_b,
    }


def run_checksum_loop(data_bytes):
    acc = 0
    for idx, b in enumerate(data_bytes):
        acc = eval_lea(acc, b, 4, idx) & 0xFFFF
    return hex(acc)


print("lea_calc=", hex(eval_lea(0x401000, index=5, scale=8, disp=0x20)))
print("cmp_0xff_vs_0x01=", compare_jumps_u8(0xFF, 0x01))
print("loop_checksum=", run_checksum_loop(b"KRN!"))
```

## Почему это работает: Зачем компилятор пишет `xor eax, eax` вместо `mov eax, 0`

При чтении листингов в `Computing 101` ты постоянно встретишь строку `xor eax, eax`. Любое число при операции `XOR` с самим собой даёт `0` (и вдобавок в `x86-64` запись в 32-битный регистр `eax` автоматически обнуляет и старшие 32 бита 64-битного регистра `rax`). Машинный код инструкции `xor eax, eax` занимает всего **2 байта** (`31 c0`), тогда как `mov eax, 0` занимает **5 байт** (`b8 00 00 00 00`) — поэтому компиляторы используют `xor` для компактности и скорости декодирования инструкций.

## Если не получилось: Частые ошибки

- **Попытка использовать в `lea` произвольный множитель `scale` (например, `7`)**: аппаратная адресация `x86-64` `[base + index*scale + disp]` поддерживает только четыре значения множителя `scale`: `1`, `2`, `4` и `8`. Чтобы умножить регистр на `3`, компилятор пишет `lea rax, [rdi + rdi*2]`, а на `5` — `lea rax, [rdi + rdi*4]`.
