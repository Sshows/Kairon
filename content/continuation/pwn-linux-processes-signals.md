## Перед началом: Как оболочка управляет запущенными программами, сигналами и цепочками команд

В модулях **Processes**, **Chaining** и **Terminal Multiplexing** практикума **Linux Luminarium** (`pwn.college`) разбирают то, что происходит с программой после её запуска: как операционная система назначает ей идентификатор процесса (`PID`), как родительский процесс узнаёт об успешном или аварийном завершении через **код возврата (exit code)** и как ядро передаёт процессам короткие асинхронные уведомления — **сигналы (signals)**.

Представь диспетчерскую службу курьерской доставки. Каждому выехавшему курьеру выдаётся уникальный номер маршрутного листа (`PID`). Когда курьер возвращается на базу, он сдаёт отчёт с числовым кодом: `0` означает «посылка доставлена без замечаний», а любое ненулевое число (`1`, `2`, `130`) сообщает причину неудачи («адрес не найден», «отказ получателя»). Если же маршрут нужно срочно отменить прямо в пути, диспетчер посылает курьеру экстренный радиосигнал: вежливую просьбу завершить смену (`SIGTERM`) или принудительное отключение (`SIGKILL`).

При автоматизации проверок в Kali Linux знание кодов возврата и сигналов необходимо постоянно: от них зависит, выполнится ли следующая команда в цепочке `cmd1 && cmd2`, как остановить зависший сетевой сканер и как перевести долгую задачу в фоновый режим (`&`, `jobs`, `fg`).

## Почему это работает: Идентификаторы PID, коды возврата и сигналы ядра

Разберём четыре механизма управления процессами в Linux:

1. **Дерево процессов (`PID` и `PPID`)**. У каждого запущенного процесса есть собственный номер `PID` (Process ID) и номер родительского процесса `PPID` (Parent Process ID), который его создал (например, оболочка `bash` или `zsh`). Когда процесс завершается, он возвращает родителю целое число от `0` до `255` — код возврата, который в оболочке сразу можно прочитать через специальную переменную `$?`.
2. **Условные цепочки команд (`&&`, `||`, `;`)**. Оболочка использует код возврата предыдущей программы, чтобы решить, запускать ли следующую:
   - `cmd1 ; cmd2` — запускает `cmd2` безусловно, даже если `cmd1` завершилась ошибкой;
   - `cmd1 && cmd2` — запускает `cmd2` **только тогда**, когда `cmd1` вернула код `0` (успех). Например, `mkdir build && cd build`;
   - `cmd1 || cmd2` — запускает `cmd2` **только тогда**, когда `cmd1` вернула ненулевой код (ошибку). Например, `ping -c 1 10.0.0.1 || echo "Узел недоступен"`.
3. **Сигналы (`SIGINT`, `SIGTERM`, `SIGKILL`, `SIGSTOP`)**. Сигнал — это номерное уведомление от ядра или другого процесса (команда `kill -s ИМЯ_СИГНАЛА PID`):
   - `SIGINT` (номер `2`, клавиши **Ctrl+C**) — запрос прерывания с клавиатуры;
   - `SIGTERM` (номер `15`, сигнал по умолчанию в `kill PID`) — штатный запрос завершения: программа может перехватить его, закрыть файлы, сохранить отчёт и аккуратно выйти;
   - `SIGKILL` (номер `9`, `kill -9 PID`) — безусловное уничтожение процесса самим ядром: программа **не может** перехватить или проигнорировать `SIGKILL`;
   - `SIGTSTP` (**Ctrl+Z**) приостанавливает процесс в памяти, позволяя перевести его в фон (`bg`) или вернуть на передний план (`fg`).
4. **Как код возврата кодирует гибель от сигнала**. По соглашению POSIX, если процесс завершился не сам, а был прерван сигналом с номером `N`, оболочка записывает в `$?` число `128 + N`. Например, после `SIGINT` (`2`) код возврата равен `130`, а после `SIGKILL` (`9`) — `137`.

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
def run_chain(steps):
    executed = []
    last_code = 0
    for idx, (op, name, exit_code) in enumerate(steps):
        should_run = (
            idx == 0
            or op == ";"
            or (op == "&&" and last_code == 0)
            or (op == "||" and last_code != 0)
        )
        if should_run:
            executed.append(f"{name}:{exit_code}")
            last_code = exit_code
    return executed, last_code


def deliver_signal(sig_name, has_handler=True):
    numbers = {"SIGINT": 2, "SIGTERM": 15, "SIGKILL": 9}
    num = numbers[sig_name]
    if sig_name == "SIGKILL":
        return "killed_by_kernel", 128 + num
    if has_handler:
        return f"graceful_shutdown:{sig_name}", 0
    return f"terminated_by:{sig_name}", 128 + num


chain_a = [
    ("START", "check_config", 0),
    ("&&", "start_worker", 1),
    ("&&", "notify_ready", 0),
    ("||", "write_error_log", 0),
]

executed, final_code = run_chain(chain_a)
print("chain_executed=", executed, "final_code=", final_code)
print("sigterm_handled=", deliver_signal("SIGTERM", has_handler=True))
print("sigkill_forced=", deliver_signal("SIGKILL", has_handler=True))
```

```bash
true && echo "step_ok" ; false || echo "fallback_ran (code=$?)"
```

Команда `true` всегда возвращает `0` (поэтому печатается `step_ok`), а команда `false` всегда возвращает `1` (поэтому срабатывает ветка после `||` и выводит `fallback_ran (code=1)`).

## Почему это работает: Зачем начинать остановку процесса с `SIGTERM`, а не с `SIGKILL`

Когда ты останавливаешь сервис базы данных, веб-сервер или скрипт сбора логов через обычный `kill PID` (`SIGTERM`), процессу даётся время сбросить буферы записи на диск и удалить временные lock-файлы. Если же сразу применять `kill -9 PID` (`SIGKILL`), ядро мгновенно отбирает память процесса, и недописанные файлы могут остаться повреждёнными. Поэтому `SIGKILL` применяют только тогда, когда процесс завис и не отреагировал на `SIGTERM`.

## Если не получилось: Частые ошибки

- **Путаница между `|` (конвейером) и `||` (логическим ИЛИ)**: одиночная вертикальная черта `cmd1 | cmd2` запускает обе команды одновременно и передаёт поток `stdout` первой на вход `stdin` второй, а двойная черта `cmd1 || cmd2` запускает вторую команду только после того, как первая завершилась с ненулевым кодом ошибки.
- **Проверка `$?` не сразу после нужной команды**: переменная `$?` хранит код возврата **самой последней** выполненной команды. Если после проверяемой программы вызвать `echo "Проверка..."`, то `$?` перезапишется кодом возврата самого `echo` (`0`). Чтобы сохранить код, его сразу записывают в переменную: `rc=$?`.
