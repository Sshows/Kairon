## Перед началом: Как связаны инструкция возврата `ret`, таблицы PLT/GOT и режим Full RELRO

В модулях **Return-Oriented Programming (ROP)** курса **Program Security** и **Exploitation Primitives** курса **Software Exploitation** (`pwn.college`) разбирают, как программа на `x86-64` управляет переходами между функциями, как вызываются внешние функции из динамических библиотек (`libc.so.6`) и как режим компоновки **Full RELRO** вместе с **CFI / Shadow Stack** перекрывает подмену указателей функций.

Представь телефонный справочник в приёмной офиса. Когда сотруднику внутри здания нужно позвонить в городскую службу доставки (внешнюю библиотеку `libc`, например функцию `puts`), он не знает её прямого внутреннего номера заранее, потому что при каждом открытии офиса (включённом **ASLR**) номера городских линий меняются. Поэтому сотрудник звонит на внутреннюю кнопку быстрого набора (**PLT — Procedure Linkage Table**), а та смотрит текущий городской номер в записной книжке на столе секретаря (**GOT — Global Offset Table**).

Если эта записная книжка (`GOT`) весь рабочий день лежит открытой для записи (`rw-`), любой сбой с перезаписью памяти может заменить номер службы доставки на номер совсем другого отдела! Именно поэтому в современных сборках Linux используют режим **Full RELRO (Relocation Read-Only)**: при старте программы загрузчик один раз заполняет всю записную книжку `GOT` и тут же убирает её под бронированное стекло **только для чтения (`r--`)**.

## Почему это работает: Гаджеты возврата, выравнивание стека 16 байт и защита таблиц GOT

Разберём устройство возвратно-ориентированных цепочек и динамического связывания:

1. **Что делает инструкция `ret` и почему цепочка управляется через `RSP`**. В архитектуре `x86-64` инструкция `ret` не знает, откуда именно была вызвана функция: она просто читает 8 байт с вершины стека (`[RSP]`), записывает их в регистр счётчика команд `RIP` и сдвигает `RSP` на 8 байт вверх (`RSP += 8`). Короткая последовательность уже существующих в секции `.text` инструкций, заканчивающаяся на `ret` (например, `pop rdi; ret`), называется **гаджетом (ROP gadget)**: `pop rdi` снимает со стека значение в регистр первого аргумента `RDI`, а следующая за ним `ret` переходит к следующему адресу на стеке.
2. **Правило выравнивания стека по границе 16 байт (System V AMD64 ABI)**. По стандарту ABI `x86-64` перед выполнением инструкции `call` указатель стека `RSP` обязан быть кратен `16` (заканчиваться на `0` в шестнадцатеричной записи). Многие функции `libc` (например, `printf`, `system`) используют векторные инструкции `movaps`, которые обращаются к стеку по 16-байтовой границе: если `RSP` сдвинут на 8 байт (не выровнен на 16), программа немедленно падает с сигналом `SIGSEGV`!
3. **Связка PLT и GOT при динамическом вызове (`Lazy Binding`)**:
   - **PLT (Procedure Linkage Table)** лежит в исполняемой секции только для чтения (`r-x`) и содержит короткий переход `jmp [GOT_entry]`;
   - **GOT (Global Offset Table)** лежит в секции данных и хранит реальные 64-битные адреса функций из `libc`.
4. **Два режима защиты RELRO (Relocation Read-Only)** и **аппаратный теневой стек (Shadow Stack / CET)**:
   - при **Partial RELRO** секция `.got.plt` остаётся доступной для записи (`rw-`) на протяжении всей работы программы, чтобы адреса разрешались «лениво» при первом вызове;
   - при **Full RELRO** (флаги компоновщика `-Wl,-z,relro,-z,now`) динамический загрузчик разрешает все адреса до входа в `main()` и переводит всю таблицу `GOT` в режим **только для чтения (`r--`)** — любая попытка перезаписать запись в `GOT` завершается `SIGSEGV`;
   - аппаратная защита **Intel CET / Shadow Stack** и **CFI (Control-Flow Integrity)** дополнительно хранит эталонные адреса возврата в отдельной защищённой области памяти: если адрес на обычном стеке `[RSP]` не совпадает с теневым стеком при выполнении `ret`, процессор мгновенно останавливает программу.

```python
def verify_rop_transition(rsp_addr, stack_ret_addr, shadow_ret_addr, check_shadow=True):
    if rsp_addr % 16 != 0:
        return "fault:unaligned_stack_movaps"
    if check_shadow and stack_ret_addr != shadow_ret_addr:
        return "fault:cet_shadow_stack_mismatch"
    return f"ret_ok:{hex(stack_ret_addr)}"


def write_got_entry(got_table, symbol, new_addr, full_relro=True):
    if full_relro:
        return "blocked:got_is_read_only_full_relro", hex(got_table[symbol])
    got_table[symbol] = new_addr
    return "modified:partial_relro", hex(got_table[symbol])


got = {"puts": 0x7FFFF7E44200, "printf": 0x7FFFF7E28100}

print("aligned_shadow_ok=", verify_rop_transition(0x7FFFFFFFE100, 0x401180, 0x401180))
print("unaligned_rsp=", verify_rop_transition(0x7FFFFFFFE108, 0x401180, 0x401180))
print("shadow_mismatch=", verify_rop_transition(0x7FFFFFFFE100, 0x401299, 0x401180))
print("got_full_relro=", write_got_entry(got, "puts", 0x401999, full_relro=True))
```

Разберём каждую строку:

## Почему это работает: Как сочетаются Full RELRO, PIE и CET

Каждая из этих мер закрывает свой класс примитивов: **PIE + ASLR** делают адреса секции `.text` и таблиц случайными при каждом запуске, **Full RELRO** запрещает перезапись указателей внешних функций в таблице `GOT`, а **CET (Shadow Stack + Indirect Branch Tracking)** проверяет целостность адресов возврата `ret` и косвенных вызовов `call rax` на аппаратном уровне процессора.

## Если не получилось: Частые ошибки

- **Почему в `x86-64` на входе в функцию сразу после `call` регистр `RSP` оканчивается на `8`, а не на `0`**: выравнивание `RSP % 16 == 0` требуется **перед** выполнением самой инструкции `call`. Инструкция `call` кладёт на стек 8-байтовый адрес возврата, сдвигая `RSP` на 8 байт, а пролог функции `push rbp` кладёт ещё 8 байт — и внутри функции стек снова оказывается выровнен по границе 16 байт!
