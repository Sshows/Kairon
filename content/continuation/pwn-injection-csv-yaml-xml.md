## Перед началом: Как обычная строка данных превращается в исполняемую директиву внутри парсера CSV, YAML и XML

В практикуме **Content Injection** (`pwncollege/injection-dojo` на платформе `pwn.college`, модули `CSV`, `YAML`, `JSON`, `XML`, `HTML/JS`) разбирают фундаментальную проблему безопасности на стыке форматов обмена данными: **контекстную инъекцию в структурированные документы**.

Представь бухгалтерию, которая выгружает ведомость заказов из интернет-магазина в таблицу Excel или LibreOffice Calc в формате `CSV`. Покупатель при оформлении заказа указывает в поле «Комментарий к доставке» строку `=SUM(1+1)` или `=HYPERLINK("http://...", "Отчёт")`. Для базы данных магазина это просто обычный текст. Но когда бухгалтер открывает выгруженный `CSV`-файл в табличном процессоре, программа видит первый символ ячейки `=` (или `+`, `-`, `@`) и решает: «О, эта ячейка начинается со знака равенства — значит, это не текст, а **формула**, которую нужно немедленно вычислить!» (**CSV Formula Injection**).

Точно такой же выход данных за пределы текстового поля происходит в конфигурациях **YAML** (когда вместо безопасного `yaml.safe_load` вызывают `yaml.load` с тегами создания произвольных объектов `!!python/object/apply:...`) и в документах **XML** (когда парсер разрешает объявление внешних сущностей `<!ENTITY xxe SYSTEM "file:///etc/hostname">`, что приводит к уязвимости **XXE — XML External Entity**).

## Почему это работает: Три механизма инъекций в структурированные форматы

Разберём устройство каждого из трёх форматов из `Content Injection Dojo` и точный способ их нейтрализации:

1. **Инъекция формул в таблицы CSV (CSV / Spreadsheet Formula Injection)**:
   - в формате `CSV` нет встроенного различия между текстом и формулой. Любое значение ячейки, начинающееся с символов `=`, `+`, `-`, `@`, а также символов табуляции `\t` (`0x09`) или возврата каретки `\r` (`0x0D`), интерпретируется табличными редакторами как исполняемая формула или вызов `DDE`;
   - **Защита**: при экспорте пользовательских строк в `CSV` каждое поле оборачивают в двойные кавычки (удвоив внутренние кавычки `"` → `""`), а если строка начинается с любого из управляющих префиксов `=`, `+`, `-`, `@`, `\t`, `\r`, перед ней ставят **одиночный апостроф `'`**, который указывает табличному редактору принудительно трактовать ячейку как чистый текст.
2. **Небезопасная десериализация в YAML (Unsafe YAML Tags)**:
   - спецификация `YAML` поддерживает специальные теги типов, начинающиеся с восклицательных знаков (`!`, `!!`). В старых конфигурациях вызов `yaml.load(data)` без указания `SafeLoader` позволял конструировать произвольные объекты языка через теги вида `!!python/...` или `!!javax.script.ScriptEngineManager`;
   - **Защита**: всегда использовать исключительно безопасный парсер (`yaml.safe_load(data)` в PyYAML), который разрешает только базовые структуры данных (строки, числа, списки, словари) и отвергает любые пользовательские теги `!` / `!!`.
3. **Внешние сущности в XML (XXE — XML External Entity)**:
   - пролог XML-документа `<!DOCTYPE root [ <!ENTITY ext SYSTEM "file:///..."> ]>` позволяет объявить именованную сущность `&ext;`, содержимое которой парсер по умолчанию пытается подгрузить из файловой системы или по сети (`http://...`);
   - **Защита**: в настройках XML-парсера (или при использовании библиотеки `defusedxml` в Python) полностью отключают обработку `DOCTYPE` (`disallow-doctype-decl`) и разрешение внешних сущностей (`resolve_entities = False`).

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
FORMULA_PREFIXES = ("=", "+", "-", "@", "\t", "\r")


def sanitize_csv_cell(value):
    text = str(value)
    if text.startswith(FORMULA_PREFIXES):
        text = "'" + text
    escaped = text.replace('"', '""')
    return f'"{escaped}"'


def inspect_structured_payload(fmt, payload):
    if fmt == "yaml":
        if "!!" in payload or "!<" in payload:
            return "blocked:unsafe_yaml_type_tag"
        return "safe_yaml_scalars_only"
    if fmt == "xml":
        upper = payload.upper()
        if "<!DOCTYPE" in upper or "<!ENTITY" in upper:
            return "blocked:xml_doctype_or_xxe_entity"
        return "safe_xml_element_tree"
    return "unknown_format"


raw_comment = '=HYPERLINK("http://127.0.0.1/collect", "Invoice")'
yaml_input = "service: web\nhandler: !!python/object/apply:os.system ['id']"
xml_input = '<?xml version="1.0"?><!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]><foo>&xxe;</foo>'

print("safe_csv_cell=", sanitize_csv_cell(raw_comment))
print("yaml_check=", inspect_structured_payload("yaml", yaml_input))
print("xml_check=", inspect_structured_payload("xml", xml_input))
print("clean_xml_check=", inspect_structured_payload("xml", "<order><id>42</id></order>"))
```

## Почему это работает: Единое правило защиты для любых текстовых форматов

Будь то `SQL`, `HTML`, `CSV`, `YAML`, `JSON` или `XML` — инъекция возникает всегда в тот момент, когда **данные пользователя склеиваются с управляющей разметкой** или передаются парсеру с включёнными возможностями выполнения кода. Надёжная защита всегда состоит из двух шагов:
1. формировать документ через строгий сериализатор формата (`csv.writer`, `json.dumps`, параметризованный SQL), а не конкатенацией строк;
2. на стороне чтения использовать только минимальный парсер данных (`yaml.safe_load`, `json.loads`, XML без `DOCTYPE` и внешних сущностей).

## Если не получилось: Частые ошибки

- **Проверка только символа `=` при защите `CSV`**: табличные редакторы выполняют формулы не только со знака `=`, но и со знаков `+`, `-` и `@` (например, `+1+1` или `@SUM(1,1)`). Поэтому проверять нужно весь набор `("=", "+", "-", "@", "\t", "\r")`.
