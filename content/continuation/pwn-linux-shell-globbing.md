## Перед началом: Почему одна и та же команда ведёт себя по-разному

Когда ты печатаешь команду в терминале Kali и нажимаешь Enter, программа запускается не сразу. Сначала строку читает **командная оболочка** (shell, например `bash` или `zsh`). Оболочка — это диспетчер на приёме заказов: прежде чем передать коробку мастеру, диспетчер сам раскрывает сокращения, делит текст по пробелам на отдельные карточки-аргументы и ищет, в каком шкафу лежит нужный инструмент.

Из-за этого новички часто путают два разных слоя: что сделала **сама оболочка до запуска** и что сделала **вызванная программа**. Например, если в папке лежит файл с именем `-n` или `-v`, и ты напишешь `cat -n`, оболочка честно передаст строку `-n` программе `cat`. Но сама программа `cat` решит, что `-n` — это не имя файла, а переключатель режима «пронумеровать строки», потому что он начинается с дефиса!

В открытом курсе **Linux Luminarium** на платформе `pwn.college` (модули `paths`, `commands`, `globbing` и `path`, открытая лицензия BSD-2-Clause) эти ситуации разбирают как фундамент работы в Linux. Сегодня мы спокойно и на своих учебных данных в Kali Linux проверим три главных механизма оболочки: шаблоны подстановки (**globbing**), защиту имён с дефисом и порядок поиска команд по переменной `PATH`.

## Почему это работает: Шаблоны оболочки, разделитель опций и маршрут PATH

Разберём три правила на жизненных примерах:

1. **Шаблоны подстановки (globbing): `*`, `?` и `[...]`**. Представь, что ты просишь архивариуса: «принеси все папки, которые начинаются на `report-` и заканчиваются на `.txt`». Архивариус сам смотрит на полку, находит `report-01.txt` и `report-02.txt` и кладёт на стол уже готовый список имён. Именно так работает оболочка: знак `*` заменяет любое количество символов (кроме точки в начале скрытого файла), знак `?` — ровно один любой символ, а `[0-9]` — один символ из указанного набора. Сама программа (`ls`, `cat`, `python3`) даже не видит звёздочку — она получает уже раскрытый список файлов. Если же взять шаблон в кавычки (`"*.txt"`), оболочка не раскрывает его и передаёт звёздочку программе буквально.
2. **Опции с дефисом и разделитель `--`**. Большинство программ Linux считают любой аргумент, начинающийся с `-`, настройкой (флагом). Чтобы сказать программе «дальше идут только имена файлов, даже если они начинаются с дефиса», используют два способа: указать путь от текущей папки (`./-secret.txt` — теперь первый символ точка, а не дефис) или поставить двойной дефис `--` (`cat -- -secret.txt`), который означает конец списка опций.
3. **Переменная окружения `PATH`**. Когда ты вводишь просто `python3` или `ls` без косой черты `/`, оболочка смотрит в список папок `PATH` (они разделены двоеточием `:`) слева направо. Первая же папка, где найдётся исполняемый файл с таким именем, выигрывает. Поэтому если в начало `PATH` случайно добавить текущую рабочую папку `.`, любая программа в этой папке сможет подменить системную команду с тем же именем.

## Сделай сейчас: Практика: проверь разбор шаблонов, флагов и PATH на модели

### Шаг 1. Сохрани код проверки в файл `lab.py`

В открытом окне редактора Mousepad вставь следующий код, нажми **Ctrl+S** и закрой редактор. Все данные создаются в памяти — никакие системные настройки Kali не меняются.

```python
import fnmatch
import posixpath

files = ["notes.txt", "report-1.log", "report-2.log", "report-10.log", "-hint.txt", ".hidden.log"]
star_match = sorted(name for name in files if not name.startswith(".") and fnmatch.fnmatchcase(name, "report-*.log"))
single_match = sorted(name for name in files if not name.startswith(".") and fnmatch.fnmatchcase(name, "report-?.log"))
print("star_match=", ",".join(star_match))
print("single_match=", ",".join(single_match))


def parse_cat_args(args):
    options = []
    targets = []
    parsing_options = True
    for item in args:
        if parsing_options and item == "--":
            parsing_options = False
            continue
        if parsing_options and item.startswith("-") and len(item) > 1:
            options.append(item)
        else:
            targets.append(item)
    return options, targets


print("naive_call=", parse_cat_args(["-hint.txt"]))
print("double_dash=", parse_cat_args(["--", "-hint.txt"]))
print("relative_path=", parse_cat_args(["./-hint.txt"]))

search_dirs = ["/usr/local/bin", "/usr/bin", "/bin"]
available = {
    "/usr/local/bin/check-tool": "custom-local",
    "/usr/bin/check-tool": "system-default",
}
resolved = next((posixpath.join(folder, "check-tool") for folder in search_dirs if posixpath.join(folder, "check-tool") in available), None)
print("resolved_path=", resolved, "variant=", available[resolved])
```

### Шаг 2. Запусти программу в терминале Kali

Вернись в окно терминала (мы уже находимся в папке `~/kairon-study/pwn-linux-shell-globbing`) и выполни:

```bash
python3 lab.py
```

**Ожидаемый результат на экране:**

```text
star_match= report-1.log,report-10.log,report-2.log
single_match= report-1.log,report-2.log
naive_call= (['-hint.txt'], [])
double_dash= ([], ['-hint.txt'])
relative_path= ([], ['./-hint.txt'])

```

Посмотри на разницу между первыми двумя строками: шаблон `report-*.log` захватил и `report-10.log` (потому что `*` заменяет любое число символов), а `report-?.log` оставил только односимвольные номера `1` и `2`. Скрытый файл `.hidden.log` не попал ни в один список, потому что обычная подстановка оболочки пропускает имена, начинающиеся с точки.

В строках `naive_call`, `double_dash` и `relative_path` видно, почему файл `-hint.txt` без защиты превращается в опцию `['-hint.txt']`, а с разделителем `--` или путём `./-hint.txt` попадает в список целевых файлов. Наконец, строка `resolved_path` показывает, что при просмотре `search_dirs` слева направо срабатывает первый найденный путь `/usr/local/bin/check-tool`.

### Шаг 3. Проверь изменение порядка папок и настоящее поведение в терминале

В файле `lab.py` поменяй местами первые две папки в списке `search_dirs`, чтобы `"/usr/bin"` шла перед `"/usr/local/bin"`, сохрани и снова запусти `python3 lab.py`. Теперь в строке `resolved_path=` появится `/usr/bin/check-tool variant= system-default`. После проверки верни исходный порядок папок.

## Почему это работает: Связь с заданиями Linux Luminarium на pwn.college

На платформе `pwn.college` в курсе **Linux Luminarium** (разделы `Paths`, `Globbing`, `The PATH`) проверочные программы часто помещают учебный файл в папку со сложным именем или просят запустить команду, когда в `PATH` не хватает нужного каталога. Понимая три правила из сегодняшнего урока, ты не угадываешь команды наугад:

- прежде чем запускать короткое имя команды, можно узнать её точное место через `which имя_команды` или `type -a имя_команды`;
- если имя файла начинается с `-`, содержит пробелы или знаки `?` и `*`, используй путь `./имя`, разделитель `--` или одиночные кавычки `'...'`;
- при проверке чужих скриптов всегда смотри, не вызываются ли внутри них команды по короткому имени без полного пути (`/usr/bin/...`), если переменная `PATH` может контролироваться пользователем.

## Если не получилось: Частые ошибки и быстрая проверка

- **Ошибка `unrecognized option` при работе с файлом в терминале**: ты передал имя файла с начальным дефисом напрямую. Поставь перед именем `--` (через пробел) или напиши `./` слитно с именем файла.
- **Шаблон `*` в терминале вывел `no matches found` (в `zsh`)**: в Kali по умолчанию используется оболочка `zsh`, которая сообщает об ошибке, если под шаблон не подошёл ни один файл. Проверь текущую папку командой `pwd` и список файлов командой `ls -la`.
- **В `lab.py` изменился вывод после правок**: убедись, что в `search_dirs` первой снова стоит папка `"/usr/local/bin"`, а шаблон в `single_match` равен `"report-?.log"`.
