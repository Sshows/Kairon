## Перед началом: Как работает символьное исполнение (`pwn.college Symbolic Execution` & `babyauto-crackmes`)

В репозиториях **`pwncollege/babyauto-crackmes`** и **`pwncollege/archive-dojo`** рассматривается один из самых красивых разделов автоматизированного анализа бинарных программ — **символьное исполнение (`Symbolic Execution`, фреймворк `angr` и решатель ограничений `Z3`)**.

Представь, что перед тобой программа `crackme`, которая читает 4 числа `(x0, x1, x2, x3)` и проверяет систему условий:
- `x0 + x1 == 100`
- `x1 - x0 == 20`
- `x2 ^ 0x55 == 0x1F`
- `x3 * 3 == 99`
Если все условия выполнены, программа открывает ветку `print("Success!")`, иначе — `print("Wrong!")`.
- **Обычный запуск (конкретное исполнение) или фаззинг** подставляет конкретные числа наугад (например, `1, 2, 3, 4`) и получает `Wrong!`.
- **Символьное исполнение (`Symbolic Execution`)** делает иначе: вместо конкретных чисел оно подаёт на вход **алгебраические переменные (символы)** $\alpha_0, \alpha_1, \alpha_2, \alpha_3$. Шагая по инструкциям процессора, движок (`angr`) на каждой развилке `if` раздваивает состояние программы:
  - в ветку «истина» он записывает математическое уравнение в копилку ограничений пути (**`Path Constraints`**);
  - когда движок доходит до желаемого адреса `target_addr` (`"Success!"`), он передаёт все накопленные уравнения в **SMT-решатель (`Z3`)**: «Найди такие значения $\alpha_0, \alpha_1, \alpha_2, \alpha_3$, при которых одновременно верны все уравнения на пути к `target_addr`, но не выполняются переходы на `avoid_addr`!»
  И решатель за миллисекунды выдаёт точный ответ без единого угадывания!

## Почему это работает: Проблема взрыва состояний (`State Explosion`) и как её укрощают в `angr`

Почему же символьное исполнение не находит автоматически все баги в мире? Из-за **комбинаторного взрыва состояний (`State Explosion`)**: если в программе 100 последовательных развилок `if/else`, то число путей равно $2^{100}$!
Чтобы `angr` не утонул в миллионах веток, аналитики используют два приёма:
1. **`avoid` (отсечение тупиковых адресов)**: сразу указывают адреса блоков `bb_fail`, чтобы движок мгновенно выбрасывал любую ветку, свернувшую на ошибку, не продолжая её анализ.
2. **Хуки (`Hooks` / `SimProcedures`)**: заменяют тяжёлые библиотечные функции с циклами (например, `strlen`, `strcmp`, `printf` или медленную проверку контрольной суммы) коротким алгебраическим правилом на Python.

### Шаг 1. Создай файл `lab.py`

Создай скрипт `lab.py`:

```python
def solve_symbolic_crackme():
    # Уравнения пути (Path Constraints) до базового блока target_addr:
    # 1) x0 + x1 == 100
    # 2) x1 - x0 == 20  => 2*x1 == 120 => x1 = 60, x0 = 40
    # 3) x2 ^ 0x55 == 0x1F
    # 4) x3 * 3 == 99
    x1 = (100 + 20) // 2
    x0 = 100 - x1
    x2 = 0x1F ^ 0x55
    x3 = 99 // 3
    return [x0, x1, x2, x3]


def verify_concrete_binary(inputs):
    x0, x1, x2, x3 = inputs
    if x0 + x1 != 100:
        return "bb_fail_stage1"
    if x1 - x0 != 20:
        return "bb_fail_stage2"
    if (x2 ^ 0x55) != 0x1F:
        return "bb_fail_stage3"
    if x3 * 3 != 99:
        return "bb_fail_stage4"
    return "bb_target_reached:FLAG_UNLOCKED"


def count_explored_states(num_branches, prune_avoid_immediately=True):
    # Без отсечения avoid число состояний удваивается на каждой проверке (2^N),
    # а при мгновенном отбрасывании ветки bb_fail продолжает идти только 1 живая ветка!
    if not prune_avoid_immediately:
        return 2**num_branches
    return num_branches + 1


solution = solve_symbolic_crackme()
verdict = verify_concrete_binary(solution)

states_no_avoid = count_explored_states(10, prune_avoid_immediately=False)
states_with_avoid = count_explored_states(10, prune_avoid_immediately=True)

print("symbolic_solution=", solution)
print("concrete_verification=", verdict)
print("states_10_branches_no_avoid=", states_no_avoid, "with_avoid=", states_with_avoid)
```

## Почему это работает: Гибридный фаззинг (`Driller` — союз фаззера и символьного исполнения)

Команда создателей `pwn.college` и `angr` разработала технику **гибридного фаззинга (`Driller`)**: пока программа проходит простые ветки, работает сверхбыстрый фаззер с покрытием (`AFL++`). Но как только фаззер застревает перед сложным 32-битным магическим условием вроде `if (crc32(buf) == 0xDEADBEEF)`, подключается символьный движок `angr`, решает это одно конкретное уравнение, кладёт новый вход в корпус фаззера — и фаззер мчится дальше!

## Если не получилось: Частые ошибки

- **Символьное исполнение криптографических хешей (`SHA-256`, `MD5`, `bcrypt`)**: односторонние криптографические функции специально спроектированы так, чтобы создавать миллионы нелинейных битовых зависимостей. Попытка решить `sha256(symbolic_input) == target` через `Z3`/`angr` зависнет навсегда — такие функции всегда заменяют заглушкой или обходят архитектурно.
