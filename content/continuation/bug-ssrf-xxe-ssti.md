## Перед началом: Три разных исполнителя за одной кнопкой

Пользователь видит поле ввода и кнопку «Показать». Внутри сайта за этой кнопкой могут стоять очень разные действия. Одно приложение скачивает картинку, другое разбирает XML-документ, третье собирает письмо из шаблона. Чтобы понять уязвимость, спроси: **какая программа получает текст и что она умеет делать с ним?**

Аналогия — поручение сотруднику офиса. «Положи эту надпись на бейдж» и «выполни написанное на листке» — разные полномочия. Ошибка возникает, когда вместо ограниченной задачи передают возможность выбирать действия. Но цифровой исполнитель действует по точным правилам: недостаточно сказать «вредная строка». Нужно найти источник значения, преобразования и операцию, до которой оно дошло.

## Почему это работает: SSRF: запрос уходит с сервера

**Server-Side Request Forgery** — ситуация, когда недоверенный ввод управляет сетевым запросом, который выполняет сервер. Например, генератор миниатюр получает адрес картинки и сам скачивает её. Запрос идёт с сервера приложения, а не с компьютера посетителя. Поэтому у него могут быть другие сетевые возможности: доступ к служебной сети или разрешения, которых нет у пользователя.

Риск не сводится к краже содержимого. Внутренний адрес может выполнять действие, даже если ответ пользователю не покажут. Проверяют разрешённое назначение, схему, порт, результат DNS и каждый переход, а также ограничивают исходящий доступ на уровне сети. Если задачу можно решить выбором картинки из серверного каталога, передавай идентификатор из этого каталога вместо произвольного URL. Такая модель проще для проверки, чем постоянное угадывание опасных адресов.

В нашем опыте каталог содержит уже сохранённые подписи картинок. Функция не скачивает ничего. Это позволяет проверить саму границу выбора, не поднимая дополнительную сеть и не делая запросы к внутренним адресам.

## Почему это работает: XXE: документ просит парсер обратиться наружу

**XML External Entity** связан с XML-парсером, который допускает внешние сущности. XML — формат структурированного текста с тегами. Некоторые возможности XML позволяют определять сущности и ссылаться на внешние ресурсы. Если парсер разрешает такой механизм для недоверенного документа, чтение документа может породить доступ к ресурсу, который приложение не намеревалось открывать.

Это не то же самое, что поле URL при SSRF: инициатором дополнительного действия становится механизм обработки XML. В конкретном приложении внешняя сущность иногда приводит и к исходящему сетевому запросу, поэтому последствия могут пересекаться. Исправление зависит от библиотеки: отключают ненужные DTD и внешние сущности, проверяют настройки загрузки внешних ресурсов, вводят ограничения размера и сложности. Поиск одного слова в документе не заменяет настройку парсера.

Ниже мы разбираем только короткий известный XML без DTD стандартной библиотекой Python. Этот один пример не удостоверяет безопасность любого XML-парсера и не является тестом всех вариантов XXE.

## Почему это работает: SSTI: пользовательский текст приняли за программу шаблона

**Server-Side Template Injection** — интерпретация недоверенного текста как исходника серверного шаблона. Шаблон напоминает бланк письма с местами для имени и суммы. Правильная граница: разработчик задаёт бланк, пользователь предоставляет значение поля. Ошибочная: из введённого значения сначала собирают новый исходник шаблона и вычисляют его.

У разных движков разный синтаксис и возможности. Строка с фигурными скобками сама по себе не является доказательством SSTI: важно, произошло ли вычисление на сервере. Вывод пользовательского HTML в браузер — другой контекст и отдельная тема XSS. Даже если шаблон не вычисляет пользовательский текст, HTML-вывод всё ещё требует контекстного экранирования.

## Сделай сейчас: Практика: три небольших действия и их границы

Сохрани в `lab.py`:

```python
from string import Template
from xml.etree import ElementTree

saved_images = {"logo": "local-logo", "help": "local-help"}
def select_image(image_id):
    return saved_images.get(image_id, "rejected")

print("image_logo=", select_image("logo"))
print("image_url=", select_image("https://example.test/image.png"))

document = "<note><title>Учебная заметка</title></note>"
root = ElementTree.fromstring(document)
print("xml_title=", root.findtext("title"))

letter = Template("Здравствуйте, $name!")
user_text = "{{ 7 * 7 }}"
print("letter=", letter.substitute(name=user_text))
print("user_text_preserved=", user_text in letter.substitute(name=user_text))
```

Выполни `python3 lab.py`. Ожидается: `image_logo= local-logo`, `image_url= rejected`, затем заголовок «Учебная заметка». В строке письма должны остаться **буквальные** символы `{{ 7 * 7 }}`, а последнее значение будет True. Число 49 не должно появляться вместо этой строки: наша программа ничего не вычисляет из пользовательского текста.

Разбор: `saved_images` — серверная таблица известных идентификаторов; пользователь выбирает ключ, а не сетевое назначение. `ElementTree.fromstring` получает одну конкретную XML-строку, `findtext` извлекает текст вложенного тега. `Template` получает фиксированный бланк. Метод `substitute` вставляет значение `name`; повторной интерпретации вставленного значения как шаблона здесь нет. Использованный синтаксис иллюстрирует сохранение текста, а не поведение всех существующих движков.

Теперь поменяй имя на `Алия` и запусти снова. Письмо изменится, структура программы останется прежней. Убери тег `<title>` из известного документа: `findtext` вернёт None, что показывает необходимость проверять обязательные поля. Сделай XML синтаксически неверным, например убери закрывающий тег: ожидается `ParseError`. Это ошибка разбора, а не признак найденной XXE. После опыта восстанови документ.

## Сделай сейчас: Как проверить настоящую систему в учебной лаборатории

Сначала составь схему пути. Для миниатюры: вход → выбор назначения → DNS → соединение → возможное перенаправление → обработка ответа. Для XML: загрузка → конкретный парсер и его настройки → извлечение значения. Для шаблона: фиксированный исходник → значения → рендеринг → вывод в нужный контекст. Отметь, какие шаги на самом деле присутствуют: не каждое приложение использует XML или шаблонизатор.

В собственной лаборатории для сетевого опыта используют свой контролируемый адрес и журнал запросов, заранее согласованный в рамках задания. Отдельно проверяют, что отказ произошёл **до** нежелательного соединения. Этот урок не предлагает обращаться к метаданным облака, файлам настоящего сервера или чужой сети. Здесь проверяются механизмы на синтетических данных; для доказательства реального влияния потребуется отдельный разрешённый стенд.

Типичная путаница: `rejected` в выборе картинки не значит, что сеть «не работает» — сетевой вызов вообще не выполнялся. Буквальный вывод `{{ 7 * 7 }}` здесь ожидаем, но не является универсальным тестом отсутствия SSTI. Ошибка XML может скрывать детали, но её одного недостаточно для вывода о внешних сущностях. В заметке обязательно назови, что именно проверил и что осталось за границами опыта.
