## Перед началом: Как быстро очищать сырые текстовые потоки и не терять запущенные задачи при обрыве связи

В модулях **Data Manipulation**, **Processes and Jobs** и **Terminal Multiplexing** практикума **Linux Luminarium** (`pwn.college`) разбирают два ежедневных навыка системного инженера и аналитика безопасности:
1. как за одну секунду извлечь нужную колонку, заменить разделители и посчитать частоту событий в большом текстовом потоке с помощью конвейера `tr | cut | sort | uniq -c`;
2. как устроено управление задачами терминала (`jobs`, `bg`, `fg`, `nohup`) и почему при работе на удалённом сервере по SSH инженеры запускают долгие проверки внутри терминального мультиплексора **`tmux`**.

Представь две ситуации. В первой тебе прислали выгрузку из 50 000 строк системного журнала, где поля разделены двоеточиями или лишними пробелами, и попросили за минуту назвать три самых активных IP-адреса. Открывать такой файл в офисном табличном редакторе долго и неудобно, а конвейер из четырёх крошечных утилит UNIX делает это за доли секунды, читая поток построчно!

Во второй ситуации ты подключился к тестовому стенду по SSH и запустил часовую проверку, но через 20 минут мигнул домашний Wi-Fi. Без мультиплексора обрыв SSH-соединения посылает всем дочерним программам терминала сигнал закрытия линии **`SIGHUP` (Hangup)**, и вся работа обрывается. Если же сессия открыта внутри **`tmux`**, сервер `tmux` продолжает работать в фоне: ты переподключаешься по SSH, вводишь `tmux attach` и видишь своё окно на том же самом месте!

## Почему это работает: Конвейер `tr` / `cut` / `sort` / `uniq` и архитектура `tmux`

Разберём оба инструментария по шагам:

1. **Четыре звена потоковой обработки текста (`Data Manipulation`)**:
   - **`tr` (translate / delete)** — заменяет или удаляет отдельные символы в потоке `stdin`. Например, `tr -s ' '` схлопывает несколько подряд идущих пробелов в один (`-s` — *squeeze*), `tr 'a-z' 'A-Z'` переводит буквы в верхний регистр, а `tr -d '\r'` удаляет виндовые возвраты каретки;
   - **`cut` (вырезка колонок)** — вырезает нужные поля из каждой строки по разделителю (`-d`) и номеру поля (`-f`). Например, `cut -d ':' -f 1,7 /etc/passwd` достаёт только имя пользователя (1-е поле) и его оболочку (7-е поле);
   - **`sort` (сортировка строк)** — выстраивает строки по алфавиту или по числовому значению (`sort -n` — по возрастанию чисел, `sort -nr` — по убыванию чисел);
   - **`uniq` (схлопывание соседних повторов)** — **важное правило**: `uniq` сравнивает только **соседние (идущие подряд)** строки! Поэтому перед `uniq` поток почти всегда сначала пропускают через `sort`. Флаг `uniq -c` считает количество повторов каждой строки, а связка `sort | uniq -c | sort -nr` строит готовый рейтинг частоты!
2. **Сессии, окна и панели в `tmux` (`Terminal Multiplexing`)**:
   - когда ты запускаешь `tmux new -s audit`, создаётся фоновый серверный процесс `tmux`, не привязанный к конкретному сетевому окну SSH;
   - нажатие префиксной комбинации **Ctrl+B**, а затем клавиши **`d` (detach)** отсоединяет твой экран от сессии, оставляя все программы работать в фоне;
   - команда `tmux ls` показывает список живых фоновых сессий, а `tmux attach -t audit` возвращает тебя обратно в сессию.

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
from collections import Counter


def pipeline_top_ips(raw_lines, delimiter="|", field_index=2):
    extracted = []
    for line in raw_lines:
        squeezed = " ".join(line.strip().split())
        parts = squeezed.split(delimiter)
        if len(parts) >= field_index:
            extracted.append(parts[field_index - 1].strip())
    counts = Counter(extracted)
    return sorted(counts.items(), key=lambda item: (-item[1], item[0]))


def naive_adjacent_uniq(items):
    result = []
    for x in items:
        if not result or result[-1] != x:
            result.append(x)
    return result


sample_logs = [
    "2026-11-08 | 10.0.0.5  | GET /login",
    "2026-11-08 | 10.0.0.12 | POST /api",
    "2026-11-08 | 10.0.0.5  | POST /login",
    "2026-11-08 | 10.0.0.5  | GET /profile",
    "2026-11-08 | 10.0.0.12 | GET /status",
    "2026-11-08 | 10.0.0.99 | GET /index",
]

raw_sequence = ["10.0.0.5", "10.0.0.12", "10.0.0.5"]

print("top_ips=", pipeline_top_ips(sample_logs, delimiter="|", field_index=2))
print("uniq_without_sort=", naive_adjacent_uniq(raw_sequence))
print("uniq_after_sort=", naive_adjacent_uniq(sorted(raw_sequence)))
```

**Ожидаемый результат на экране:**

uniq_without_sort= ['10.0.0.5', '10.0.0.12', '10.0.0.5']

Обрати внимание на разницу:
- функция `pipeline_top_ips` сжала лишние пробелы (аналог `tr -s ' '`), вырезала второе поле по разделителю `|` (аналог `cut -d '|' -f 2`) и построила частотный рейтинг по убыванию: `10.0.0.5` встретился 3 раза, `10.0.0.12` — 2 раза, `10.0.0.99` — 1 раз;
- в `uniq_without_sort` список `['10.0.0.5', '10.0.0.12', '10.0.0.5']` подали в `uniq` без предварительной сортировки: так как два одинаковых адреса `10.0.0.5` разделены строкой `10.0.0.12` и не стоят рядом, дубликат **не удалился**;
- в `uniq_after_sort` предварительный вызов `sorted(...)` поставил одинаковые строки рядом, и `uniq` оставил ровно два уникальных адреса `['10.0.0.12', '10.0.0.5']`.

## Почему это работает: Как `SIGHUP` связан с фоновыми задачами и `tmux`

Когда закрывается окно обычного терминала или рвётся сессия SSH, ядро Linux отправляет ведущему процессу сессии (оболочке `bash`) сигнал **`SIGHUP` (Hangup, номер `1`)**, а оболочка пересылает его своим дочерним задачам. Чтобы задача пережила отключение терминала, используют либо запуск внутри сессии **`tmux`** / `screen`, либо обёртку `nohup команда &` (которая перенаправляет вывод в `nohup.out` и игнорирует сигнал `SIGHUP`).

## Если не получилось: Частые ошибки

- **Вызов `uniq -c` без предварительного `sort`**: самая частая ошибка при анализе логов. Если строки не отсортированы, `uniq -c` посчитает только подряд идущие серии, и один и тот же IP-адрес появится в отчёте несколько раз в разных строках. Всегда пиши связку `sort | uniq -c`.
- **Попытка передать в `cut -d` разделитель из нескольких символов**: классическая утилита `cut` принимает в `-d` ровно **один** символ (например, `-d ':'` или `-d ','`). Если поля разделены произвольным числом пробелов, сначала сожми пробелы через `tr -s ' '` или используй `awk '{print $2}'`.
