## Перед началом: Как работает арифметика с остатком в основе RSA и почему «учебный RSA» без схемы OAEP уязвим

В модулях **Basic Mathematics** и **RSA** практикума **Cryptographic Exploitation (Cryptomania)** на платформе `pwn.college` разбирают математический фундамент асимметричной криптографии (криптографии с открытым ключом): как работает **сравнение по модулю (Modular Arithmetic)**, обратный элемент в кольце вычетов `pow(e, -1, phi)` и почему прямое применение формулы $c = m^e \bmod n$ («учебный» или *Textbook RSA*) без рандомизированной упаковки **RSA-OAEP** позволяет извлечь открытый текст обычным корнем третьей степени!

Представь обычный циферблат механических часов от `0` до `11` (арифметика по модулю $12$). Если сейчас `9` часов и прошло `5` часов, стрелка показывает не `14`, а остаток от деления $14$ на $12$ — то есть `2` часа ($9 + 5 \equiv 2 \pmod{12}$). В криптосистеме **RSA** вместо числа $12$ выбирают произведение двух огромных секретных простых чисел $n = p \cdot q$. Возвести сообщение $m$ в открытую степень $e$ по модулю $n$ ($c = m^e \bmod n$) легко любому, кто знает открытый ключ $(n, e)$. А вот чтобы выполнить обратную операцию — извлечь корень степени $e$ по модулю $n$ ($m = c^d \bmod n$), нужно знать секретный показатель $d$, который вычисляется через функцию Эйлера $\varphi(n) = (p - 1)(q - 1)$ как модульное обратное: $e \cdot d \equiv 1 \pmod{\varphi(n)}$.

Но что произойдёт, если разработчик решил зашифровать короткий PIN-код или короткий сессионный ключ $m$ напрямую («в лоб», без схемы дополнения **OAEP**) с малым открытым показателем $e = 3$? Если само число $m^3$ оказалось **меньше** модуля $n$ ($m^3 < n$), то взятие остатка $\bmod\, n$ вообще ничего не отсекло! Тогда $c = m^3$ как обычное целое число, и любой перехватчик мгновенно найдёт $m = \sqrt[3]{c}$ на обычном калькуляторе без всякого секретного ключа $d$!

## Почему это работает: Генерация ключей RSA, атака малого показателя ($m^3 < n$) и защита RSA-OAEP

Разберём математику RSA и её практическую защиту по шагам:

1. **Как связаны открытый ключ $(n, e)$ и закрытый ключ $d$**:
   - выбираются два больших случайных простых числа $p$ и $q$, перемножаются в модуль $n = p \cdot q$;
   - вычисляется $\varphi(n) = (p - 1)(q - 1)$ и выбирается открытая экспонента $e$ (в современных стандартах почти всегда $e = 65537$), взаимно простая с $\varphi(n)$;
   - закрытая экспонента $d$ находится алгоритмом Евклида как обратный элемент: в Python 3 это записывается одной встроенной командой **`d = pow(e, -1, phi)`**;
   - шифрование: `c = pow(m, e, n)`, расшифровка: `m = pow(c, d, n)`.
2. **Почему «учебный RSA» (Textbook RSA) никогда не используют напрямую**:
   - **Уязвимость короткого сообщения при малом $e$ (`Cube Root Attack`)**: если $m$ мало и $e = 3$, так что $m^3 < n$, то $c = m^3 \bmod n = m^3$, и $m$ восстанавливается обычным целочисленным корнем третьей степени;
   - **Детерминированность**: без случайной добавки одно и то же сообщение $m$ (например, `"YES"` или `"NO"`) при шифровании открытым ключом всегда даёт один и тот же шифротекст $c$, позволяя угадать ответ простым перебором словаря;
   - **Мультипликативность (гомоморфность)**: $(m_1 \cdot m_2)^e \bmod n = (m_1^e \cdot m_2^e) \bmod n$, что позволяет подделывать подписи без хеширования и комбинировать перехваченные шифротексты.
3. **Как работает стандартная защита `RSA-OAEP` (для шифрования) и `RSA-PSS` (для подписи)**:
   - перед возведением в степень схема **OAEP (Optimal Asymmetric Encryption Padding)** генерирует случайное зерно (`random seed`), расширяет сообщение с помощью криптографических хеш-функций (MGF1) на всю ширину модуля $n$ (чтобы полученное число гарантированно было сопоставимо с $n$ и $x^e \gg n$) и делает каждое шифрование вероятностным.

### Шаг 1. Сохрани код в файл `lab.py`

Вставь следующий код в открытый редактор Mousepad, нажми **Ctrl+S** и закрой редактор:

```python
import hashlib


def integer_cbrt(x):
    lo, hi = 0, x
    while lo <= hi:
        mid = (lo + hi) // 2
        cube = mid**3
        if cube == x:
            return mid
        if cube < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1


def rsa_setup(p, q, e=3):
    n = p * q
    phi = (p - 1) * (q - 1)
    d = pow(e, -1, phi)
    return n, e, d


def oaep_like_encode(msg_int, n_bits=32, seed=b"nonce-01"):
    mask = int.from_bytes(hashlib.sha256(seed).digest()[:3], "big")
    high_bit = 1 << (n_bits - 2)
    return high_bit | (mask << 8) | (msg_int & 0xFF)


n, e, d = rsa_setup(65537, 65543, e=3)
short_m = 42

raw_cipher = pow(short_m, e, n)
recovered_without_key = integer_cbrt(raw_cipher)

padded_m = oaep_like_encode(short_m, n_bits=32)
padded_cipher = pow(padded_m, e, n)
cube_root_on_padded = integer_cbrt(padded_cipher)
decrypted_padded = pow(padded_cipher, d, n) & 0xFF

print("raw_m3_less_than_n=", short_m**3 < n, "cube_root_recovered=", recovered_without_key)
print("padded_m3_wraps_mod_n=", padded_m**3 > n, "cube_root_on_padded=", cube_root_on_padded)
print("proper_key_decrypt=", decrypted_padded)
```

Разберём, что показала проверка:
- модуль $n = 65537 \times 65543 = 4\,295\,501\,091$. Когда мы зашифровали короткое число `short_m = 42` напрямую («учебным RSA» с $e = 3$), его куб $42^3 = 74\,088$ оказался намного меньше модуля $n$ (`raw_m3_less_than_n= True`). Поэтому взятие остатка `pow(42, 3, n)` вообще не изменило число $74\,088$, и функция `integer_cbrt` мгновенно извлекла секрет `42` без закрытого ключа `d`!
- когда же перед возведением в степень мы расширили сообщение на всю ширину блока со случайной маской (`oaep_like_encode`), куб числа `padded_m` многократно превысил модуль $n$ (`padded_m3_wraps_mod_n= True`) и свернулся по модулю $n$. Прямое извлечение кубического корня стало невозможным (`cube_root_on_padded= -1`), а штатная расшифровка закрытым ключом `pow(padded_cipher, d, n)` точно вернула исходное значение `42`.

## Почему это работает: Два правила безопасного использования RSA в реальных системах

1. Всегда использовать стандартный открытый показатель **$e = 65537$** (`0x10001`) и схему дополнения **RSA-OAEP** (для шифрования) или **RSA-PSS** (для цифровых подписей).
2. Никогда не шифровать большие объёмы данных напрямую через RSA: в реальных протоколах (TLS, PGP, Age) асимметричный алгоритм (или обмен ключами `X25519` / `ML-KEM`) передаёт только случайный 256-битный ключ, а сами данные шифруются быстрым аутентифицированным шифром **AEAD (`AES-GCM` или `ChaCha20-Poly1305`)**.

## Если не получилось: Частые ошибки

- **Вызов ` (m ** e) % n` вместо трёхместного `pow(m, e, n)` в Python**: выражение `(m ** e) % n` сначала пытается вычислить гигантское число $m^e$ целиком в оперативной памяти (что для 2048-битных ключей зависнет на часы и исчерпает всю память), тогда как `pow(m, e, n)` использует быстрое возведение в степень по модулю, беря остаток на каждом шаге битового сдвига за доли миллисекунды!
