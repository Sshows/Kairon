## Перед началом: Задача: заметить изменение, которое легко пропустить глазами

В прошлом уроке ты проверял главную страницу своего сервиса и отсутствующий путь. Теперь представь обычную рабочую ситуацию: разработчик исправил вход, а после обновления страница входа начала возвращать ошибку. Главная страница по-прежнему открывается. Проверка только главной скажет «всё работает» и пропустит проблему.

Нам нужен **эталон**: сохранённый и проверенный набор ожиданий. Это похоже на акт приёма квартиры. В нём записано, что работало при передаче: окно открывается, розетка выдаёт питание, ключ подходит к двери. При следующем осмотре мы сравниваем конкретные свойства. Любое отличие требует объяснения, но само по себе ещё не устанавливает, кто виноват и был ли умысел.

В автоматизации такую разницу часто называют **diff**. Программа не понимает весь смысл приложения. Она выполняет заданные сравнения. Если в список проверок не включено право пользователя на заказ, сравнение заголовков не обнаружит ошибку доступа. Это ограничение нужно помнить до запуска скрипта.

## Почему это работает: Какие поля сравнивать

HTTP-ответ состоит из статуса, заголовков и тела. Статус 200 и статус 500 означают разные результаты обработки. Заголовок Content-Type сообщает, каким типом содержимого сервер считает тело. Cache-Control определяет правила кеширования. Изменение этих полей бывает значимым, но ожидаемое значение зависит от маршрута: публичная картинка и личный профиль не обязаны иметь одинаковую политику кеша.

Дата, время выполнения и случайный идентификатор запроса обычно меняются при каждом вызове. Если сравнивать весь ответ как один текст, отчёт наполнится шумом. Мы явно выбираем поля сравнения, а время сохраняем только как контекст. При этом «не сравниваем» не означает «время не важно»: для скорости нужен отдельный опыт с несколькими измерениями и допустимыми границами.

В этом занятии мы используем **две заранее заданные записи**, чтобы отчёт был одинаковым и его можно было проверить вручную. Никаких запросов в интернет программа не делает. Предыдущий HTTP-проверяющий нужен, чтобы понимать, откуда подобные записи могут появиться в настоящей проверке. Мы не выдаём синтетические данные за результат проверки опубликованного Kairon.

## Сделай сейчас: Практика: сравни два наблюдения

Сохрани следующий код в открытом файле `lab.py`. Здесь нет адреса компьютера или домена, который нужно заменить. `/` и `/login` — ключи учебного словаря, а не команды терминала.

```python
import json

baseline = {
    "/": {"status": 200, "content_type": "text/html", "cache": "public", "ms": 12},
    "/login": {"status": 200, "content_type": "text/html", "cache": "no-store", "ms": 18},
}
current = {
    "/": {"status": 200, "content_type": "text/html", "cache": "public", "ms": 17},
    "/login": {"status": 500, "content_type": "text/html", "cache": "no-store", "ms": 25},
}
fields = ("status", "content_type", "cache")
changes = []
for path in sorted(set(baseline) | set(current)):
    if path not in baseline:
        changes.append({"path": path, "change": "new_route"})
        continue
    if path not in current:
        changes.append({"path": path, "change": "missing_observation"})
        continue
    for field in fields:
        if baseline[path][field] != current[path][field]:
            changes.append({"path": path, "field": field,
                            "before": baseline[path][field],
                            "after": current[path][field]})
print(json.dumps(changes, ensure_ascii=False, indent=2))
```

В терминале выполни:

```bash
python3 lab.py
```

Программа должна вывести список из **одного изменения**: путь `/login`, поле `status`, прежде 200, теперь 500. Значения `ms` различаются у обеих страниц, но в список `fields` они не входят. Поэтому строк о времени нет. Мы не потеряли данные: они остаются во входных наблюдениях, просто не участвуют в этом сравнении.

Разберём код. Словарь `baseline` хранит прежние значения, `current` — новые. `set(baseline) | set(current)` собирает все пути из обоих наблюдений, а `sorted` делает порядок вывода постоянным. Два условия `if` обрабатывают появившийся путь и отсутствующее наблюдение. Отсутствие записи не называют автоматически удалением страницы: возможно, сборщик просто не проверил её. Внутренний цикл читает каждое выбранное поле. Если значения различны, в отчёт добавляется маленькая запись с адресом, названием поля и обеими версиями значения.

## Сделай сейчас: Проверь программу изменением одного условия

В `current` у `/login` замени только `cache` с `no-store` на `public`, сохрани файл и повтори запуск. Теперь ожидаются **две записи**: о статусе и о кеше. Не меняй `baseline`, иначе поменяешь само основание сравнения. Затем верни статус в 200: должна остаться только разница кеша. Так мы проверяем, что скрипт реагирует на нужное поле, а не просто печатает заранее написанный ответ.

Хочешь сохранить отчёт — выполни `python3 lab.py > diff.json`. Знак `>` заменит содержимое файла `diff.json` в текущей папке. Перед повторным опытом переименуй важный старый отчёт. В настоящей работе вместе с результатом хранят дату, версию приложения, окружение и метод сбора. Сравнение тестовой версии с рабочей без этой пометки может выглядеть как поломка после обновления, хотя сравнивались разные системы.

## Сделай сейчас: Что делать с найденным отличием

Отчёт — повод для проверки. Сначала вручную повтори запрос в той же среде. Затем проверь, согласовано ли изменение: возможно, путь намеренно закрыли. Если отличие связано с личными данными или доступом, отдельно проверь содержимое ответа и права двумя своими тестовыми аккаунтами. Не заменяй эталон автоматически после каждого запуска: тогда нежелательное изменение станет «нормой» и исчезнет из следующего отчёта.

Типичные ошибки: `SyntaxError` после вставки означает, что нарушены кавычки, запятые или отступы; сравни ближайшие строки с кодом. `can't open file` означает, что терминал не видит `lab.py` в текущей папке; выполни `pwd` и `ls`. Пустой список `[]` допустим, если все выбранные поля совпадают. Он не означает отсутствие всех возможных уязвимостей.

Итоговая заметка может выглядеть так: «В двух сохранённых наблюдениях путь /login изменил статус с 200 на 500. Время намеренно исключено из сравнения. Реальный сетевой запрос этим скриптом не выполнялся. Следующий шаг — повторить проверку на своей тестовой версии и сверить журнал ошибки». Это точнее и полезнее фразы «автоматизация нашла взлом».
