## Перед началом: Что делает John the Ripper

John the Ripper — программа для проверки паролей по их хешам. В разговорах название иногда запоминают как «Jack the Ripper», но инструмент в Kali называется **John**. Его задача — брать варианты пароля, вычислять для них значение нужного формата и сравнивать с имеющимся образцом. Он не получает исходный пароль обычным «обратным расшифрованием хеша».

Представь, что у тебя есть проверочная карточка для кодового замка. Можно взять предполагаемый код, получить для него карточку тем же способом и сравнить. Если карточки совпали, найден подходящий кандидат. Скорость и успех зависят от алгоритма, параметров и списка догадок. Если нужного варианта в коротком словаре нет, такой словарный опыт его не найдёт.

Важно различать **офлайн-проверку** и **онлайн-попытки входа**. При офлайн-проверке программа работает с полученным для проверки хешем на твоём компьютере. Вход на сайт не выполняется, серверные лимиты попыток не участвуют. Онлайн-подбор отправляет запросы к реальному механизму входа. Поэтому защиту паролей в базе и защиту формы входа проектируют отдельно.

## Почему это работает: Почему формат хеша нужно знать

Длинная шестнадцатеричная строка не всегда позволяет однозначно определить алгоритм. Существуют быстрые хеши, солёные форматы, специальные функции обработки паролей и разные способы записи результата. Опция `--format` выбирает, **что именно** John будет проверять. Неверный формат может дать сообщение о невозможности загрузить образец или отсутствие результатов.

Соль — дополнительное значение, используемое при обработке пароля. Обычно её не скрывают как пароль: она мешает одинаковым паролям автоматически давать одинаковый результат у разных пользователей и уменьшает пользу заранее рассчитанных таблиц. Соль не заменяет стойкий пароль и подходящую дорогостоящую функцию обработки, например Argon2id, scrypt или корректно настроенный bcrypt.

В учебном опыте ниже используется быстрый несолёный SHA-256 только для наглядности. Это позволяет быстро проверить три заранее известных кандидата. Такой опыт не является рекомендацией хранить пользовательские пароли как обычный SHA-256.

## Сделай сейчас: Создай свои данные для проверки

Открой терминал Kali:

```bash
mkdir -p ~/kairon-reading/john
cd ~/kairon-reading/john
python3 - <<'PY'
from pathlib import Path
import hashlib
password = "Kairon-demo-42"
Path("hash.txt").write_text(hashlib.sha256(password.encode()).hexdigest() + "\n")
Path("words.txt").write_text("apple\nKairon-demo-42\norange\n")
print("Created one training hash and three candidates")
PY
```

`mkdir -p` создаёт отдельную папку, `cd` делает её текущей. `~` — твоя домашняя папка. Блок после `python3 -` передаётся Python через стандартный ввод; строка `PY` завершает его. Кавычки вокруг первого `PY` защищают содержимое от подстановок оболочки.

`encode()` переводит текст учебного пароля в байты, `sha256` вычисляет хеш, `hexdigest` делает шестнадцатеричную запись. Файл `hash.txt` содержит одну строку с этим значением. В `words.txt` находятся ровно три кандидата, включая выбранный нами пароль. Никакие файлы аккаунтов операционной системы здесь не читаются.

Проверь `cat words.txt` и `cat hash.txt`. Первая команда должна показать три понятные строки. Вторая — одну строку из 64 шестнадцатеричных символов. Если видишь лишние кавычки вокруг хеша или имя файла рядом, ты сохранил не тот формат, который ожидает этот опыт.

## Сделай сейчас: Запусти словарную проверку в Kali

Сначала выполни `john`. Без аргументов программа покажет справку. Если команды нет, установи пакет `sudo apt install john` после обновления списка пакетов. В Kali используется расширенная сборка; доступные форматы можно посмотреть:

```bash
john --list=formats
john --format=raw-sha256 --wordlist=words.txt --pot=training.pot hash.txt
john --show --format=raw-sha256 --pot=training.pot hash.txt
```

`--list=formats` перечисляет поддерживаемые этой сборкой форматы. `--format=raw-sha256` указывает, что наш образец — простой SHA-256 без дополнительной структуры. `--wordlist=words.txt` выбирает файл кандидатов. `hash.txt` в конце — файл проверяемых хешей. Это не адрес сайта и не команда получить чужие пароли.

`--pot=training.pot` сохраняет результаты именно этого опыта в отдельном файле. `--show` показывает уже найденные соответствия. В выводе должен присутствовать `Kairon-demo-42`; оформление строки и дополнительные показатели зависят от версии сборки. Учебный пароль специально известен заранее, поэтому результат можно проверить независимо.

Не переписывай приглашение вроде `kali@...` или `$` из чужого скриншота. Команда начинается со слова `john`. Для повторного опыта используй новую отдельную папку или другое имя pot-файла: сохранённый результат может означать, что при следующем запуске John сразу сообщит об уже проверенном хеше.

## Если не получилось: Как понять сообщения и ограничения

`No password hashes loaded` обычно требует проверить содержимое файла, формат и поддерживаемые алгоритмы. `Unknown ciphertext format name requested` указывает на неподдерживаемое имя формата или другую сборку. В таком случае не нужно менять исходный хеш на случайный алгоритм: сначала сверь `john --list=formats` и происхождение пакета.

Если John пишет, что новых хешей для проверки нет, посмотри `--show` с тем же `--pot`. Возможно, результат уже сохранён. Если результат не найден, проверь наличие точного кандидата в `words.txt`, регистр, пробелы и переносы. Неудача на трёх словах доказывает только отсутствие совпадения среди этих кандидатов, а не стойкость любого пароля против всех способов проверки.

Hashcat решает похожую общую задачу и также поддерживает разные форматы и режимы, часто используя ускорение на подходящем оборудовании. Название программы само по себе не определяет, будет ли конкретный пароль найден. Важны формат, параметры, ресурсы, модель кандидатов и выбранные ограничения времени.

## Сделай сейчас: Что должен понять защитник

Для базы паролей нужны подходящая функция обработки с солью и стоимостью, защита самой базы и серверных секретов. Для формы входа — ограничения попыток, дополнительные факторы и наблюдение за подозрительными входами. MFA помогает защитить аккаунт, но не превращает опубликованный слабый пароль в сильный.

Итог занятия запиши так: «Я создал собственный учебный SHA-256, проверил три кандидата и нашёл заранее заданный пароль. Офлайн-проверка не обращалась к форме входа. Результат ничего не говорит о паролях других людей или обо всех возможных форматах хранения». Полезные справки: [Kali John](https://www.kali.org/tools/john/) и [опции Openwall](https://www.openwall.com/john/doc/OPTIONS.shtml).
