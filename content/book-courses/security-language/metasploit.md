## Перед началом: Что такое Metasploit Framework

Metasploit Framework — среда для работы с отдельными модулями проверки и исследования. Её удобно представить как мастерскую с инструментами и общим рабочим столом. У каждого инструмента есть назначение, подходящие условия и настройки. Наличие мастерской не означает, что любая задача решается одной кнопкой.

Основной консольный интерфейс называется `msfconsole`. Это отдельная программа со своими командами. Команды `search`, `use` и `show options` вводятся уже **внутри её консоли**, а команда запуска `msfconsole` — в обычном терминале Kali. Путаница между двумя окнами приводит к сообщениям `command not found` даже при правильном названии внутренней команды.

В первом опыте мы выберем модуль определения HTTP-сервера и направим его только на собственный локальный сервис. Так можно увидеть общий рабочий цикл без сложного эксплойта и без предположений о чужих системах.

## Почему это работает: Разбери основные виды модулей

**Auxiliary** — категория вспомогательных задач, например сбора сведений или проверки протокола. Название категории не обещает, что любой её модуль всегда безвреден: нужно читать описание конкретной задачи и понимать, какие запросы она отправляет.

**Exploit** — модуль, использующий конкретную уязвимость при подходящих условиях. Ошибка в названии версии, платформе или предварительных условиях может сделать проверку неприменимой. Успешное обнаружение названия продукта по заголовку HTTP ещё не доказывает, что конкретная уязвимость существует.

**Payload** — код или действие, которое должно выполняться в контексте конкретного сценария. Это не синоним самой уязвимости. **Post** — модули для работы после получения соответствующей сессии. Сессия — существующее взаимодействие с удалённым контекстом, а не просто запись найденного IP в таблице.

CVE — идентификатор опубликованной записи об уязвимости. Он помогает ссылаться на один случай, но не является командой эксплуатации. Модуль, CVE, версия продукта, предварительные условия и фактическое поведение — разные части доказательства, которые исследователь связывает между собой.

## Сделай сейчас: Подготовь свой HTTP-сервис

В первом терминале Kali запусти:

```bash
mkdir -p ~/kairon-reading/msf
cd ~/kairon-reading/msf
printf 'Kairon module practice\n' > index.html
python3 -m http.server 8767 --bind 127.0.0.1
```

Мы создали отдельную папку и простой текст страницы. `8767` — выбранный порт. `127.0.0.1` означает эту же Kali: Windows на основном компьютере имеет собственный loopback. Оставь процесс работать и во втором терминале проверь `curl -i http://127.0.0.1:8767/`. Должны прийти HTTP-ответ и наша учебная строка.

Если `curl` не получает ответ, сначала исправь обычный сервис. Неправильный адрес или выключенный сервер не становятся правильными из-за запуска более сложного инструмента. Эта предварительная проверка позволит потом отличить проблему стенда от поведения модуля.

## Сделай сейчас: Открой консоль и изучи модуль

Во втором терминале выполни `msfconsole -q`. Опция `-q` уменьшает приветственный вывод. Если программа отсутствует, пакет Kali называется `metasploit-framework`; его установка может потребовать заметно больше места, чем небольшой Python-скрипт. Перед установкой посмотри предлагаемый менеджером пакетов размер и доступное место.

Внутри консоли выполни по очереди:

```text
help
search type:auxiliary name:http_version
use auxiliary/scanner/http/http_version
info
show options
```

`help` показывает команды текущего интерфейса. `search` ищет метаданные модулей; условия `type:auxiliary` и `name:http_version` ограничивают поиск. Мы выбираем модуль по полному пути, а не по номеру строки выдачи: номера могут меняться между версиями и запросами.

`use` делает модуль текущим; приглашение консоли обычно начинает показывать его контекст. `info` выводит описание, авторов и доступные сведения. `show options` показывает таблицу имён параметров, текущих значений и обязательности. Сначала прочитай, какую задачу выполняет выбранный модуль. В данном случае он отправляет HTTP-запрос и пытается описать HTTP-сервис по ответу.

## Сделай сейчас: Задай ровно свою цель и выполни проверку

```text
set RHOSTS 127.0.0.1
set RPORT 8767
set SSL false
show options
run
```

`set` задаёт значение параметра выбранного модуля. `RHOSTS` здесь — адрес проверяемого сервиса, `RPORT` — его порт. Суффикс `R` исторически указывает на сторону цели; цель вполне может быть локальной. `SSL false` соответствует нашему открытому HTTP, а не HTTPS.

Перед `run` ещё раз посмотри таблицу. Она должна указывать именно `127.0.0.1` и `8767`. Наш пример не требует подсети, списка внешних узлов или адреса Kairon. `run` запускает выбранную вспомогательную проверку. В первом терминале появится запрос к собственному Python-серверу; в консоли — результат определения сервиса, если модуль смог его получить.

Оформление строки, определённая версия и детали fingerprint зависят от установленного Metasploit и ответов сервера. Ожидаемый смысл — распознан HTTP-сервис нашего стенда. Это не означает получение доступа к системе или подтверждение какой-либо CVE. Заголовок с версией может быть изменён самим приложением; его рассматривают как наблюдение, которое при необходимости проверяют другими способами.

## Сделай сейчас: Что означают другие часто встречающиеся слова

`LHOST` и `LPORT` относятся к локальной стороне некоторых сценариев, например адресу и порту для определённого обратного соединения. Их смысл нужно читать в контексте конкретного модуля и выбранного способа связи. Они не означают автоматически «всегда впиши любой IP своей Kali». Наличие VPN, NAT и нескольких интерфейсов влияет на достижимость адресов.

Команда `check` существует у части модулей и может помочь проверить условия, но она не является универсальной гарантированно пассивной кнопкой. Нужно изучить описание и реализацию конкретного модуля. Рейтинг модуля тоже не означает, что любой узел с похожим баннером уязвим или что проверка гарантированно успешна.

Для выхода из контекста модуля используй `back`, для завершения консоли — `exit`. Затем останови свой Python-сервер через Ctrl+C в первом терминале. Если Metasploit сообщает об отсутствии подключения к базе, некоторые вспомогательные задачи всё ещё могут работать, но сохранение результатов и функции базы требуют отдельной настройки. Для этого вводного опыта не нужно менять рабочую Neon-базу Kairon.

## Сделай сейчас: Как сформулировать результат

Запиши модуль, его назначение, адрес и порт собственного стенда, параметры и фактический ответ. Правильный вывод: «Вспомогательный модуль обратился к моему HTTP-сервису и получил сведения из ответа». Неправильное расширение вывода: «Metasploit нашёл версию, значит, сервер взломан».

Команды и путь модуля сверены с [документацией Framework](https://docs.metasploit.com/docs/using-metasploit/basics/using-metasploit.html) и [его исходником](https://github.com/rapid7/metasploit-framework/blob/master/modules/auxiliary/scanner/http/http_version.rb). Для дальнейшей работы полезнее научиться читать условия и подтверждать результат, чем запоминать много названий модулей без понимания их действий.
