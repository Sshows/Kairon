## Общая идея инъекции

Инъекция возникает, когда данные, пришедшие из менее доверенного источника, начинают участвовать в формировании инструкций для другого интерпретатора. В зависимости от места это может быть SQL, командная оболочка, браузерный HTML/JavaScript, язык шаблонов или иной механизм.

Представь бланк заказа, где клиент должен написать только название товара. Если сотрудник воспринимает написанное как новое распоряжение «выдать все товары со склада», граница между данными и управляющей командой потерялась. В цифровой системе такое различие задаётся конкретным синтаксисом и интерфейсом передачи значений.

Одна найденная кавычка или странная строка ещё не является доказанной уязвимостью. Нужно проследить значение до чувствительного действия, понять контекст и показать изменение поведения. Защита тоже зависит от места: параметризация SQL, безопасная работа с аргументами процесса и корректный вывод в браузере решают разные задачи.

## SQL-инъекция: данные меняют условие запроса

Открой терминал Kali, создай папку `~/kairon-reading/injections`, перейди в неё через `cd` и в Mousepad сохрани `sql_demo.py`:

```python
import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE users (name TEXT)")
db.executemany("INSERT INTO users VALUES (?)", [("anna",), ("boris",)])

def wrong(value):
    query = "SELECT name FROM users WHERE name = '" + value + "'"
    return db.execute(query).fetchall()

def correct(value):
    return db.execute("SELECT name FROM users WHERE name = ?", (value,)).fetchall()

for value in ["anna", "' OR 1=1 --"]:
    print("input:", repr(value))
    print("before:", wrong(value))
    print("after: ", correct(value))
db.close()
```

Это собственная временная база в памяти процесса. `CREATE TABLE` создаёт таблицу, `executemany` вставляет двух вымышленных пользователей. В функции `wrong` значение вклеивается внутрь SQL-текста между кавычками. Поэтому специально сформированное значение может закрыть строку, добавить условие и изменить смысл запроса.

В учебном вводе `' OR 1=1 --` первая кавычка завершает строковое значение, `OR 1=1` делает условие истинным, а `--` начинает комментарий для остатка этой строки SQL. Такая запись имеет смысл именно в показанном контексте. В другой СУБД, другом запросе или при правильной передаче параметров результат будет другим.

Функция `correct` задаёт структуру запроса отдельно и передаёт значение через параметр `?`. Кортеж `(value,)` содержит один элемент: запятая нужна синтаксису Python. Драйвер обрабатывает содержимое как значение, а не как добавленный SQL-код. Мы не пытаемся вручную «убрать все опасные символы».

Запусти `python3 sql_demo.py`. Для `anna` обе функции вернут только Анну. Для специальной строки первая вернёт обе записи, вторая — пустой список: пользователя с таким буквальным именем нет. Тем самым показаны и нарушение ожидаемого выбора, и сохранение обычного сценария после исправления.

Параметры обычно предназначены для значений, а не для произвольных имён таблиц или ключевых слов SQL. Если продукт позволяет выбирать сортировку, разработчик может сопоставить известное имя варианта с заранее определённым фрагментом запроса. Передать целый пользовательский SQL-текст как «параметр» и ожидать автоматической безопасности нельзя.

## XSS: браузер получает активное содержимое

Cross-Site Scripting относится к выполнению кода в контексте веб-страницы. При reflected XSS ввод возвращается в текущем ответе; при stored XSS сохраняется и попадает в последующие страницы; при DOM-based XSS опасный путь обработки находится в клиентском коде. Эти названия помогают описать путь данных, но сами не заменяют анализ конкретного места вывода.

Посмотри на безвредный пример различия данных и HTML. Создай `html_demo.py`:

```python
from html import escape
from pathlib import Path

value = "<b>TRAINING-MARKER</b>"
page = "<!doctype html><meta charset='utf-8'><title>Data and HTML</title>"
page += "<h1>Direct HTML</h1><div>" + value + "</div>"
page += "<h1>Text in HTML</h1><div>" + escape(value) + "</div>"
Path("output.html").write_text(page, encoding="utf-8")
print("Created output.html")
```

Запусти `python3 html_demo.py` и открой созданный файл в браузере. В первом блоке слово будет выделено жирным: `<b>` интерпретировался как HTML-тег. Во втором увидишь запись тегов как текст. Здесь нет JavaScript и кражи данных; опыт показывает необходимую для понимания XSS границу интерпретации.

`escape` подходит для показанного текстового места внутри HTML. Другие контексты требуют других правил. Вставка значения внутрь JavaScript, URL или CSS не становится безопасной только потому, что где-то вызвана HTML-функция. На стороне браузера для обычного текста часто используют `textContent`, а не `innerHTML`; фреймворки имеют свои безопасные механизмы и способы явно их обойти.

Сам факт жирного текста ещё не доказывает выполнение JavaScript. HTML-инъекция и XSS связаны, но результат нужно называть точно. Для подробного разбора контекстов продолжай уроки Kairon по XSS и защите вывода; наличие HTTPS не устраняет такую ошибку приложения.

## Command injection: оболочка читает строку как программу

Командная оболочка понимает специальные символы: разделители, перенаправления и подстановки. Если приложение склеивает пользовательское значение с командной строкой и передаёт её оболочке, ввод может изменить состав выполняемых действий.

Для обычного запуска известной программы часто лучше передавать отдельные аргументы с `shell=False`. Создай `args_demo.py`:

```python
import subprocess
import sys

value = "hello; THIS_IS_ONLY_TEXT"
result = subprocess.run(
    [sys.executable, "-c", "import sys; print(sys.argv[1])", value],
    capture_output=True, text=True, check=True, timeout=3,
)
print(result.stdout.strip())
```

Запусти `python3 args_demo.py`. Вся строка с точкой с запятой должна напечататься буквально. Мы запускаем известный интерпретатор и передаём значение одним аргументом; командная оболочка эту строку не разбирает. `check=True` делает ненулевой код завершения ошибкой, `timeout=3` ограничивает ожидание, `capture_output` позволяет получить вывод программы.

Это не универсальное оправдание передавать любые аргументы любой программе. Сам запущенный инструмент может понимать специальные опции, пути или собственный язык выражений. Если пользователь управляет именем исполняемого файла, частью кода после `-c` или опасной опцией, граница остаётся проблемной. В примере все эти части фиксированы, меняется только обычное текстовое значение.

## Остальные похожие названия

**SSTI** — внедрение выражений в серверный шаблон: важен факт обработки ввода как шаблонного языка, а не просто появления фигурных скобок на странице. **LDAP injection** относится к построению LDAP-фильтра. **NoSQL injection** зависит от языка и драйвера конкретной базы: иногда проблема возникает, когда клиенту позволяют передать оператор вместо ожидаемого простого значения.

**SSRF** — другая распространённая ошибка: приложение делает серверный запрос по назначению, на которое повлиял пользователь. Здесь главный вопрос — какие адреса, схемы, перенаправления и сетевые возможности доступны серверу. Называть любой URL-параметр подтверждённой SSRF нельзя. **CSRF** — использование браузера пользователя для нежелательного действия в его авторизованном контексте; это также отдельная граница, а не другое название XSS.

После занятия составь свою таблицу: «источник значения → интерпретатор или действие → нарушенное правило → исправление → обычный контрольный случай». Для SQL это параметры, для HTML — безопасный вывод в конкретном контексте, для процесса — управляемые программа и аргументы. Такая таблица помогает отвечать по смыслу, даже когда вопрос сформулирован непривычно и ни один знакомый инструмент в нём не назван.
