## Перед началом: Что автоматизировать после ручной проверки

Ты изменил настройки своего учебного сервиса и хочешь каждый раз проверять одинаковые вещи: отвечает ли главная страница и как сервер сообщает об отсутствующем файле. Вручную это можно открыть в браузере. Скрипт пригодится, когда проверку нужно повторять после каждого изменения и сохранять результаты в одинаковом виде.

Представь курьера у дома. Есть несколько разных исходов: он не дозвонился до домофона, охрана ответила, но не нашла нужного жильца, либо посылку приняли. В сети тоже нельзя свести всё к фразе «сайт не работает». Ошибка соединения возникает до HTTP-ответа. HTTP 404 уже является ответом сервера: запрошенный ресурс не найден. HTTP 200 означает успешную обработку запроса по правилам приложения; он сам по себе не доказывает безопасность и правильность всего сайта.

В примерах Black Hat Python сетевой клиент помогает увидеть передачу байтов напрямую. Здесь мы сначала воспользуемся библиотекой HTTP, чтобы не перепутать логику протокола с ручной сборкой пакетов. Наша программа проверит ровно два известных адреса собственного сервиса. Это маленькая повторяемая проверка, а не автоматический поиск уязвимостей на произвольных сайтах.

## Сделай сейчас: Подними сервис в отдельном терминале

Открой **первое** окно терминала Kali:

```bash
mkdir -p ~/kairon-reading/http
cd ~/kairon-reading/http
printf 'Kairon local service\n' > index.html
python3 -m http.server 8765 --bind 127.0.0.1
```

`mkdir -p` создаёт папку, `cd` делает её текущей. `printf` выводит указанный текст; `\n` добавляет перенос строки. Знак `>` направляет вывод в файл и заменяет его прежнее содержимое — здесь это наш учебный `index.html`. Перед выполнением проверь, что находишься в специально созданной папке.

В последней команде `-m` просит Python запустить модуль `http.server`. Число `8765` — выбранный порт. `--bind 127.0.0.1` ограничивает прослушивание этой машиной: сервис доступен приложениям внутри твоей Kali. Адрес `127.0.0.1` в Windows будет означать Windows, а не соседнюю виртуальную машину. Оставь окно открытым: сервер занимает терминал и ждёт запросы.

Во **втором** терминале проверь вручную:

```bash
curl -i http://127.0.0.1:8765/
curl -i http://127.0.0.1:8765/missing
```

`curl` выполняет HTTP-запрос. Параметр `-i` показывает заголовки вместе с телом ответа. В первом случае ищи статус `200` и текст `Kairon local service`. Во втором ожидается `404`. Не создавай файл `missing`, иначе ожидаемый результат изменится. Это и есть предварительные условия проверки, которые обязательно нужно записывать.

## Сделай сейчас: Создай проверяющий скрипт

Во втором терминале перейди в учебную папку и открой Mousepad. Сохрани там файл `check_http.py` со следующим кодом:

```python
import json
from urllib.request import Request, build_opener, ProxyHandler, HTTPRedirectHandler
from urllib.error import HTTPError, URLError

class NoRedirect(HTTPRedirectHandler):
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None

base = "http://127.0.0.1:8765"
opener = build_opener(ProxyHandler({}), NoRedirect())
results = []
for path in ["/", "/missing"]:
    request = Request(base + path, headers={"User-Agent": "Kairon-local-check"})
    try:
        with opener.open(request, timeout=3) as response:
            sample = response.read(200).decode("utf-8", errors="replace")
            results.append({"path": path, "status": response.status, "sample": sample})
    except HTTPError as error:
        results.append({"path": path, "status": error.code})
        error.close()
    except (URLError, TimeoutError) as error:
        results.append({"path": path, "transport_error": type(error).__name__})

print(json.dumps(results, ensure_ascii=False, indent=2))
```

`urllib` входит в стандартную библиотеку. `base` содержит фиксированный адрес нашего сервиса; программа не принимает чужой домен из файла. Список путей тоже явно задан. `ProxyHandler({})` отключает использование proxy из переменных окружения: учебный запрос не должен случайно отправляться через сторонний прокси.

Класс `NoRedirect` останавливает автоматический переход по перенаправлению. HTTP-библиотека обычно умеет сама идти на новый URL из заголовка `Location`; для контролируемой проверки нужно отдельно решить, разрешено ли новое назначение. Возврат `None` не даёт нашей программе следовать туда автоматически. У локального `http.server` эти два пути не должны перенаправлять, но ограничение делает границу программы явной.

`Request` описывает запрос. Заголовок `User-Agent` помогает отличать его в собственном журнале сервера, но не даёт дополнительных прав. `timeout=3` ограничивает ожидание сетевой операции; это не строгий общий таймер всей программы. `read(200)` читает не более 200 байт тела, потому что для проверки не нужно скачивать весь ответ. Декодирование превращает байты в текст; `errors="replace"` заменит неподходящие последовательности, а не оборвёт весь отчёт.

## Сделай сейчас: Раздели ответы сервера и ошибки связи

Запусти во втором терминале:

```bash
cd ~/kairon-reading/http
python3 check_http.py
```

В списке результатов первая запись должна содержать `"status": 200`, вторая — `"status": 404`. Библиотека сообщает о 404 через исключение `HTTPError`, хотя сервер ответил. Поэтому мы обрабатываем его отдельно и сохраняем код. Если смешать все исключения, программа ошибочно назовёт нормальный ответ 404 «отсутствием связи».

Теперь в первом терминале нажми **Ctrl+C**, чтобы остановить свой сервер. Повтори `python3 check_http.py` во втором. Вместо HTTP-статусов появится `transport_error`. Точный класс может зависеть от системы и причины отказа. Сравни условия: адрес не менялся, но процесса, принимающего соединение, больше нет. Верни сервер той же командой и убедись, что статусы снова появились.

Для сохранения наблюдения можно выполнить `python3 check_http.py > check-result.json`. Оболочка запишет вывод в файл. Имя файла выбираешь ты; при повторе с тем же именем старый результат заменится. Чтобы сравнивать несколько запусков, используй понятные разные имена и запиши время, версию приложения и условия проверки.

## Если не получилось: Как читать результат и расширять программу

Сообщение сервера `Address already in use` означает, что порт уже занят. Возможно, первое окно всё ещё работает. Не запускай много одинаковых копий. Если выберешь другой порт, поменяй его и в команде сервера, и в `base`. Бесконечное ожидание часто появляется у программ без тайм-аута; именно поэтому мы задали его явно.

Этот проверяющий полезен для вопроса «повторяется ли ожидаемое поведение двух путей». Он не проверяет авторизацию, SQL-запросы, TLS или всю работу приложения. Следующее осмысленное улучшение — добавить к каждой записи ожидаемый статус и сравнивать факт с ожиданием, сохраняя сам факт даже при расхождении. Затем можно отдельно проверять известный короткий маркер в ответе.

Законченный проект должен уметь объяснить свой отказ: неверный HTTP-статус, неожиданное содержимое или отсутствие связи — разные ситуации и разные действия разработчика. Так автоматизация помогает человеку думать точнее, а не прячет разные ошибки за одной красной надписью.
