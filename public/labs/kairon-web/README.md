# Kairon: как защищают веб-приложение

Это собственные учебные примеры Kairon, а не сервер Juice Shop. Они не открывают порты, не отправляют запросы и не используют настоящие аккаунты. Python создаёт учебные состояния в памяти; закрытие программы их удаляет. output-demo.html сравнивает только фиксированную безопасную разметку.

1. Скачай ZIP со страницы курса и распакуй. Имя `kairon-web` — название учебной папки, не имя ПК или пользователя.
2. Открой эту папку файловым менеджером Kali → «Открыть терминал здесь». Проверь `pwd` и `ls`: рядом должны быть practice.py, output-demo.html и READY.txt.
3. Если папка действительно лежит в домашнем каталоге и называется kairon-web, можно вместо этого выполнить `cd ~/kairon-web`. `~` автоматически обозначает твою домашнюю папку.
4. Выполняй по одному: `python3 practice.py sessions`, `python3 practice.py authentication`, `python3 practice.py authorization`, `python3 practice.py sql`, `python3 practice.py csrf`.
5. Для главы про вывод текста открой output-demo.html двойным щелчком в браузере. HTML не требует сервера или установки пакетов.

Только стандартная библиотека Python 3. Не нужно sudo, pip или подключение к базе. Два заказа в SQLite существуют лишь в оперативной памяти этого процесса. Демонстрация authentication моделирует уже полученные ответы проверок; она не реализует настоящий парольный вход, TOTP или passkeys. Пример сессии показывает отзыв и срок действия, а не готовую библиотеку аутентификации. CSRF — модель серверного решения, не воспроизведение реального браузерного запроса.

Читай полный разбор команд и ограничений в уроках. Не переноси упрощённые функции в рабочую систему вместо проверенных библиотек.
