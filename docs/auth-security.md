# Аккаунты и разделение данных — 0.14

Вход необязателен для бесплатных уроков. Аккаунт используется для серверных
отметок, закладки и заметки. Auth.js Credentials создаёт JWT-сессию в HttpOnly
cookie (Secure в production, SameSite=Lax), срок — 8 часов. Каждый защищённый
запрос проверяет актуальные blocked, emailVerifiedAt и sessionVersion в БД.
Восстановление пароля увеличивает sessionVersion и отзывает старые сессии.

## Регистрация и восстановление

Zod нормализует почту, ограничивает длину полей и отклоняет лишние поля,
включая role/userId. Пароль: минимум 12 символов, не более 72 байт UTF-8;
bcrypt cost 12. При входе неизвестный аккаунт также проходит сравнение с
фиктивным bcrypt-хешем, который не связан с учётной записью.

Код из 6 цифр создаётся crypto.randomInt. База получает HMAC-SHA256 от
назначенного challenge ID и кода с серверным AUTH_SECRET, а не сам код.
Challenge ID — случайный UUID. Код живёт 10 минут, допускает пять попыток.
Функция проверки блокирует строку FOR UPDATE: конкурентная проверка не может
повторно использовать код. Повторный запрос удаляет предыдущий challenge той
же почты и назначения. Регистрация не обновляет уже существующий аккаунт.
До подтверждения запись User не создаётся. Восстановление меняет пароль и
версию сессии, сохраняя идентификатор, роль и учебную историю.

Все лимиты атомарны и общие для экземпляров Vercel, хранятся в PostgreSQL:

| Операция | Лимит |
| --- | --- |
| Вход на почту | 8 попыток за 15 минут |
| Вход с IP | 30 попыток за 15 минут |
| Запросы писем с IP | 8 за час |
| Запросы писем на почту | 1 за 60 секунд и 3 за 15 минут |
| Запросы писем суммарно | 180 за сутки |
| Проверки кодов с IP | 30 за 15 минут, плюс 5 на challenge |

Ключи лимитов — HMAC, в таблице нет открытых IP/адресов. На Vercel используется
заголовок x-vercel-forwarded-for, выставленный платформой; локально — общий
тестовый ключ, произвольному X-Forwarded-For доверия нет. Лимиты не заменяют
защиту инфраструктуры от распределённого отказа в обслуживании и могут
затрагивать людей за одним общим IP. Ответ выдачи challenge одинаков по
форме для существующего/неизвестного адреса; постоянное время SMTP-запроса
не гарантируется. Ошибки драйвера/SMTP, пароли и коды не выводятся в логи.

## Защита запросов

Auth.js обеспечивает CSRF для входа/выхода. /api/account и /api/progress
принимают только JSON с совпадающим Origin, ограничивают реальный поток тела
16 KB и проверяют строгую схему. ID урока должен существовать, день — 1–60,
урок закладки должен принадлежать этому дню, заметка — до 1000 символов.
Ответы персональных API имеют Cache-Control: private, no-store и Vary: Cookie.

Сервер получает полномочия только из сессии. accountId в теле — дополнительная
проверка устаревшей вкладки, а не источник полномочий. Несовпадение даёт 409.
Все действия фильтруются по userId и дополнительно ограничены FORCE RLS.
Гость получает 401 при попытке записать серверный прогресс.

## Роли PostgreSQL

- Владелец по DIRECT_URL: миграции и обслуживание; не используется Vercel.
- kairon_runtime: LOGIN без владения таблицами, BYPASSRLS, superuser,
  CREATEROLE, CREATEDB и членства в других ролях. Имеет ограниченный доступ к
  собственным строкам и вызов узких серверных функций.
- kairon_auth: NOLOGIN, владелец SECURITY DEFINER-функций. Имеет ровно права
  для выдачи кода, создания пользователя и смены хеша/подтверждения/версии
  сессии; не имеет UPDATE роли. У функций фиксирован search_path=pg_catalog,
  таблицы квалифицированы public, PUBLIC не имеет EXECUTE.

FORCE RLS действует на User, AuditLog, LoginAttempt, LessonProgress,
EmailChallenge, StudyDayProgress, StudyBookmark. withUser использует
set_config('app.user_id', ..., true) внутри транзакции; после завершения
контекст исчезает и не переносится через pooled соединение Neon.

Это дополнительная защита от пропущенного фильтра в доверенном серверном
коде. Владелец украденного runtime-DSN может сам задавать custom settings:
RLS с общей служебной ролью не делает прямой SQL-доступ безопасным для ученика.
DSN не выдаётся браузерам, урокам или сторонним MCP-клиентам. Заметки хранятся
обычным текстом, не имеют сквозного шифрования и доступны оператору БД.

## Состояние браузера

Аккаунт не записывается в гостевой localStorage. Импорт гостевых результатов
требует явного действия. При входе/выходе весь документ перезагружается,
вкладки получают уведомление. Старый асинхронный ответ не заменяет данные
нового аккаунта. Неуспешное сохранение не изображается успешной галочкой.
Отметки — самостоятельный учебный учёт, не защищённые экзаменационные оценки;
/api/learning остаётся общедоступной самопроверкой без оплаты и XP.

## Почта и секреты

Gmail SMTP: TLS на 465 с проверкой сертификата, отдельный пароль приложения,
фиксированные отправитель/текст/тема. Только SMTP_USER и SMTP_PASSWORD на
сервере. Публичного маршрута чтения кода нет. Локальный тестовый SMTP —
отдельный процесс, слушающий только loopback; приложение разрешает его лишь
вне Vercel при KAIRON_TEST_MAIL=1 и AUTH_URL=http://localhost:3000.
.env.local, .vercel и Prisma client исключены из Git. Секреты не коммитятся.
