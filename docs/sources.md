# Kairon: аудит внешних компонентов

Проверено: 24 октября 2026 года. Это предварительный выбор компонентов, а не отчет об их установке. Через GitHub прочитаны метаданные, корневые деревья, README и файлы лицензий; для HackTools также package.json. Код сторонних проектов, установщики и лаборатории не запускались. Полный аудит безопасности, зависимостей и совместимости версий еще требуется перед каждым внедрением.

## Решение для MVP

Ядро обучения, учетные записи, последовательное открытие заданий, начисление XP, проверки, админку и MCP-интерфейс пишем в Kairon. Готовыми берем отдельно запускаемые учебные цели: сначала DVWA, затем Juice Shop. Wazuh, WebGoat, Guacamole и GOAD относятся к последующим этапам. Каталоги public-apis и awesome-mcp-servers помогают выбрать источники, но сами не предоставляют backend или SDK Kairon.

## API для справочных виджетов

- **CVE:** NVD указан в public-apis. Официальная [документация NVD](https://nvd.nist.gov/developers/vulnerabilities) в этом проходе открылась без доступного текста; лимиты и актуальный API-контракт здесь не подтверждены. Это кандидат, не готовая интеграция.
- **Подтвержденные эксплуатируемые уязвимости:** официальный [cisagov/kev-data](https://github.com/cisagov/kev-data) содержит JSON, CSV и JSON Schema. README указывает CC0. Предпочесть этот первоисточник сторонней RapidAPI-обертке, найденной в public-apis.
- **Репутация IP:** [AbuseIPDB CHECK](https://docs.abuseipdb.com/#check-endpoint) — чтение, нужен API-ключ. Не подключать REPORT/BULK-REPORT: учебный проект не должен отправлять внешние жалобы.
- **Справка по IP/ASN:** [IPinfo](https://ipinfo.io/developers) документирует токен, включая Lite. Каталог public-apis указывает отсутствие авторизации, поэтому нельзя переносить этот столбец как проверенный факт.
- Запросы внешних API выполняет сервер сайта с кешем; учебные контейнеры остаются без Интернета. В MVP достаточно заранее сохраненного учебного набора с явной датой. Реальные тарифы и условия хранения данных проверять перед подключением; в этом аудите покупок или регистрации ключей не было.

## Изоляция: требование к следующему этапу

`internal: true` само по себе не доказывает отсутствие доступа к хосту. Docker прямо указывает, что контейнер во внутренней сети может обращаться к адресу шлюза и доступным там сервисам хоста. Источник: [Docker network internal mode](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode---internal).

Поэтому приемка лабораторного сервера должна проверять отдельно: недоступность Интернета, хоста и metadata endpoint; отсутствие доступа к чужим сессиям; отсутствие Docker socket/host mounts/privileged режима; лимиты CPU/RAM/PID и время жизни. Нужны сетевые правила на хосте/гипервизоре и автоматические негативные тесты. Доступ к терминалу идет через авторизованный шлюз, а учебные порты не публикуются напрямую. Для заданий с повышением привилегий внутри машины нужно отдельно оценить VM/microVM вместо обещания абсолютной защиты общим Docker-ядром.

Модели и пакеты скачиваются при контролируемой сборке образов. Во время урока Ollama работает локально; облачные fallbacks отключены. Тесты и эталонные ответы хранятся в доверенной части проверки, которую студент не может подменить.
